# 힌트 / 포기 규칙

## 고정 조건 (API)

출처: `docs/api/game-v2.md`, `docs/api/openapi.json`

- 힌트 API `hint/{rank}`: `0 ~ 999`만 가능 (범위 밖 → 422). `0`은 정답 초성
- 추측 응답 `rank`: 순위권이면 `1 ~ 999`, 순위 밖이면 `-1`, 정답이면 `null`
- 1위 = 정답을 제외하고 가장 가까운 단어
- 힌트 / 포기 API 호출은 서버 통계에 기록됨 (호출할 때마다)

용어
- **최고 순위**: 지금까지 나온 단어 중 가장 높은 순위. 순위 밖(-1)과 초성 힌트(0)는 제외 (초성 행이 들어가면 일반 힌트가 막힘)
- **일반 힌트**: `hint/{1~999}`, 힌트 버튼으로 요청
- **초성 힌트**: `hint/0`, 포기 버튼으로 요청. 포기하려는 유저에게 포기 대신 초성을 보여줘 계속 플레이하도록 유도하는 장치
- **힌트 버튼 비활성은 일반 힌트에만 해당**: 최고 순위가 몇 위든 초성 힌트(포기 버튼)는 막지 않음

## A. 일반 힌트 순위

| # | 항목 | 규칙 |
|---|---|---|
| A-1 | 순위권 단어가 없을 때(입력 없음 / 순위 밖 단어만) 첫 힌트 | **999위** |
| A-2 | 최고 순위 200 ~ 999위일 때 다음 힌트 | A-5 공식 적용 (950→713) |
| A-3 | 최고 순위 101 ~ 199위일 때 다음 힌트 | A-5 공식 적용 (150→113, 101→76) |
| A-4 | 최고 순위 21 ~ 100위일 때 다음 힌트 | A-5 공식 적용 (100→75, 30→23, 21→20) |
| A-5 | 다음 힌트 순위 공식 | **비율 0.75**: `max(A-6, round(최고 순위 × 0.75))`<br>999→749→562→422→317→238→179→134→101→76→57→43→32→24→20 (A-6이 20일 때 총 15회) |
| A-6 | 힌트 한계 순위: 힌트로 줄 수 있는 가장 높은 순위이자, 최고 순위가 이 값 이내면 일반 힌트를 막는 기준 | **20위** (20위 이내 = "아주 유사"의 기준점). 비활성은 **힌트 버튼에만** 적용, 초성 힌트(포기 버튼)는 영향 없음 |
| A-7 | 힌트로 받은 단어도 다음 힌트의 기준(최고 순위)이 되는지 | 됨. 힌트는 항상 이전 최고 순위보다 높게 주므로, 받은 순간 최고 순위가 됨 |

## B. 초성 힌트

포기 버튼을 눌렀을 때 포기를 막고 계속 플레이하도록 유도하는 장치. 일반 힌트(A)의 비활성 기준과 무관.

| # | 항목 | 규칙 |
|---|---|---|
| B-1 | 사용 조건 | 조건 없음. 포기 버튼을 누를 수 있으면 언제든 (입력 0개여도 가능) |
| B-2 | 받는 경로 | 포기 버튼 → 확인 창에서 선택: "초성 힌트 받고 계속 도전하기" / "정말로 포기할래요". 포기 버튼을 누르는 것만으로는 지급하지 않음 |
| B-3 | 초성 힌트 사용 후 일반 힌트 | 계속 사용 가능 (초성 힌트 단어는 최고 순위 기준에서 제외) |
| B-4 | 힌트 사용 횟수 포함 여부 | 횟수의 기준은 **서버 `hint_count`** (결과 공유·랭킹용). 초성 힌트를 따로 구분할지는 랭킹 설계 때 결정 (`docs/todo/results.md`)<br>프론트 `hintUsed`는 일반 힌트만 세며 Amplitude 분석용으로만 사용 |
| B-5 | 하루 사용 횟수 | 1회. 초성 힌트 선택지는 미사용일 때의 확인 창에만 노출 (C-2). 사용 여부는 localStorage에 저장돼 새로고침 후에도 유지. 훅에서도 사용 여부 확인 (D-2 연속 클릭 방어) |

## C. 포기

| # | 항목 | 규칙 |
|---|---|---|
| C-1 | 포기 가능 조건 | 정답 맞히기 전이면 언제든 (입력 0개여도 가능). 실수 방지는 확인 창으로 처리 (C-2) |
| C-2 | 포기 확인 창 구성 | 초성 힌트 미사용: B-2와 동일<br>사용 후: "계속 도전하기" / "포기하기"<br>공통: 창 닫기(X / 바깥 클릭 / ESC) = 아무것도 안 하고 계속 플레이. 계속 플레이 쪽이 기본 선택, "포기하기"는 위험 동작 스타일로 구분. 포기 결과(C-5)를 창에 명시 (예: "포기하면 정답이 공개되고, 이후 입력하는 단어는 오늘 기록에 반영되지 않아요") |
| C-3 | 포기 버튼 비활성 조건 | 게임 종료(정답 / 포기) 시에만 비활성. 그 외 비활성 조건이 없으므로 안내 문구 없음 |
| C-4 | 포기 시 기록할 시도 횟수 | **입력 횟수 그대로(N).** 포기는 입력이 아니므로 +1 하지 않음 (포기 시 추가되는 정답 행 attempt도 N). 결과 창, 친구 비교 바, 공유 링크, Amplitude 모두 같은 값. 공유 관련은 `docs/todo/share.md` |
| C-5 | 포기 후 단어 입력 | **입력 허용, 기록은 고정.** 정답을 맞혀도 포기 기록 유지, 축하 효과 없음. 포기 이후 입력은 서버 통계(제출 횟수·성공 여부)에 반영되지 않음. D-1과 동일한 "게임 종료 후 자유 탐색" 정책<br>포기 후 정답 단어 입력: 포기 시 정답 행이 목록에 추가되므로 이미 제출한 단어로 처리 |

## D. 공통 / 예외

| # | 항목 | 규칙 |
|---|---|---|
| D-1 | 정답을 맞힌 뒤 힌트 / 초성 힌트 / 포기 / 입력 처리 | 힌트·포기 버튼 비활성. 단어를 더 넣어보는 재미를 위해 입력은 허용 (서버 제출 횟수 통계에는 미반영) |
| D-2 | 요청 중 다시 누르면? | **응답 오기 전까지 버튼 잠금** (성공/실패 후 해제, 이후 활성 여부는 A-6·B-5·게임 종료 규칙으로 판단)<br>- 일반 힌트: 힌트 버튼 잠금<br>- 초성 힌트 / 포기: 같은 버튼이므로 하나의 잠금 공유, 포기 버튼 잠금<br>- 단어 제출: 입력창·제출 버튼 잠금 |
| D-3 | 힌트 / 포기 요청 실패 시 처리 | 실패 토스트, 상태 변경 없음. 잠금 해제 후 버튼으로 재시도<br>참고: 3초 타임아웃 시 서버는 처리했을 수 있음 (힌트 → `hint_count`만 증가, 포기 → 서버는 포기 기록, 화면은 진행 중) |
| D-4 | 새로고침 후에도 유지해야 하는 상태 | 게임 상태 전체(localStorage). 포기 버튼은 별도 상태가 없으므로 새로고침과 무관하게 항상 확인 창부터 뜸 |
