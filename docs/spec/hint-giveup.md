# 힌트 / 포기 규칙

- **정할 것**: 결정이 필요한 정책. 먼저 확정한 뒤 구현을 맞춘다
- **현재 구현**: `bugfix` 브랜치 미커밋 코드(`useGameState.ts`, `GiveUpButton.tsx`, `NewMantleForm`) 기준 동작
- **변경사항**: 확정된 정책 기입

## 고정 조건 (API)

출처: `docs/api/game-v2.md`, `docs/api/openapi.json`

- 힌트 API `hint/{rank}`: `0 ~ 999`만 가능 (범위 밖 → 422). `0`은 정답 초성
- 추측 응답 `rank`: 순위권이면 `1 ~ 999`, 순위 밖이면 `-1`, 정답이면 `null`
- 1위 = 정답을 제외하고 가장 가까운 단어
- 힌트 / 포기 API 호출은 서버 통계에 기록됨 (호출할 때마다)

용어
- **최고 순위**: 지금까지 나온 단어 중 가장 높은 순위. 순위 밖(-1)과 초성 힌트(0)는 제외 (초성 행이 들어가면 일반 힌트가 막힘)
- **일반 힌트**: `hint/{1~999}`, 힌트 버튼으로 요청
- **초성 힌트**: `hint/0`, 포기 버튼으로 요청. 포기하려는 유저에게 포기 대신 초성을 보여줘 계속 플레이하도록 유도하는 장치
- **힌트 버튼 비활성은 일반 힌트에만 해당**: 최고 순위가 몇 위든 초성 힌트(포기 버튼)는 막지 않음

## A. 일반 힌트 순위

| # | 정할 것 | 현재 구현 | 변경사항 |
|---|---|---|---|
| A-1 | 순위권 단어가 없을 때(입력 없음 / 순위 밖 단어만) 첫 힌트는 몇 위? | 900위 | **999위** |
| A-2 | 최고 순위 200 ~ 999위일 때 다음 힌트는 몇 위? | 100위 위 (950→850) | A-5 공식 적용 (950→713) |
| A-3 | 최고 순위 101 ~ 199위일 때 다음 힌트는 몇 위? | 100위 위, 최소 20위 (150→50, **101→20**) | A-5 공식 적용 (150→113, 101→76) |
| A-4 | 최고 순위 21 ~ 100위일 때 다음 힌트는 몇 위? | 20위 위, 최소 20위 (100→80, 30→20, 21→20) | A-5 공식 적용 (100→75, 30→23, 21→20) |
| A-5 | 구간을 고정 간격으로 나눌지, 하나의 공식(예: 현재 순위의 일정 비율)으로 통일할지 | 100위 기준으로 간격 100 / 20 고정 | **비율 0.75로 통일**: `max(A-6, round(최고 순위 × 0.75))`<br>999→749→562→422→317→238→179→134→101→76→57→43→32→24→20 (A-6이 20일 때 총 15회) |
| A-6 | 힌트 한계 순위: 힌트로 줄 수 있는 가장 높은 순위이자, 최고 순위가 이 값 이내면 일반 힌트를 막는 기준 | 20위 (20위 이내면 버튼 비활성) | 하나의 값으로 통일, **20위 유지** (20위 이내 = "아주 유사"의 기준점). 비활성은 **힌트 버튼에만** 적용, 초성 힌트(포기 버튼)는 영향 없음 |
| A-7 | 힌트로 받은 단어도 다음 힌트의 기준(최고 순위)이 되는지 | 됨 (요청한 순위를 그 단어 순위로 저장) | 유지. 힌트는 항상 이전 최고 순위보다 높게 주므로, 받은 순간 최고 순위가 됨 |

## B. 초성 힌트

포기 버튼을 눌렀을 때 포기를 막고 계속 플레이하도록 유도하는 장치. 일반 힌트(A)의 비활성 기준과 무관.

| # | 정할 것 | 현재 구현 | 변경사항 |
|---|---|---|---|
| B-1 | 사용 조건: 언제든 / 일반 힌트를 다 쓴 뒤 / 최소 입력 수 등 | 조건 없음 (입력 0개여도 가능) | 유지 (포기 버튼을 누를 수 있으면 언제든) |
| B-2 | 받는 경로: 포기 버튼 첫 클릭 시 바로 지급 / 확인 창에서 선택 / 별도 버튼 | 포기 버튼 첫 클릭 시 확인 창 없이 바로 지급. 이후 확인 창에도 "초성 힌트 보기" 버튼 노출 | **바로 지급 제거.** 포기 버튼 → 확인 창에서 선택: "초성 힌트 받고 계속 도전하기" / "정말로 포기할래요" (실수로 눌러 초성 힌트를 받는다는 피드백 반영) |
| B-3 | 초성 힌트 사용 후에도 일반 힌트를 계속 쓸 수 있는지 | 가능 (초성 힌트 단어는 기준에서 제외) | 유지 |
| B-4 | 힌트 사용 횟수에 포함하는지 | 프론트 `hintUsed`: 포함 안 됨. 단, `hintUsed`는 Amplitude "Game Given Up" 이벤트에만 쓰이고 화면 표시 없음<br>서버 `hint_count`(친구 결과 비교 "친구 힌트 n회 사용"에 표시): `hint/0` 호출도 포함되는지 백엔드 확인 필요 | 횟수의 기준은 **서버 `hint_count`** (결과 공유·랭킹용). 초성 힌트를 따로 구분할지는 랭킹 설계 때 결정 (`docs/todo/ranking.md`)<br>프론트 `hintUsed`는 Amplitude 분석용으로만 사용 |
| B-5 | 하루 몇 번 쓸 수 있는지 | 1회 — UI에서만 막음 (확인 창에 버튼 미노출), 훅은 확인 안 함 | 1회. 초성 힌트 선택지는 미사용일 때의 확인 창에만 노출 (C-2). 사용 여부는 localStorage에 저장돼 새로고침 후에도 유지. 훅에서도 사용 여부 확인 (D-2 연속 클릭 방어) |

## C. 포기

| # | 정할 것 | 현재 구현 | 변경사항 |
|---|---|---|---|
| C-1 | 포기 가능 조건: 언제든 / 최소 입력 수 / 힌트 사용 후 등 | 정답 맞히기 전이면 언제든 (입력 0개여도 가능) | 유지 (실수 방지는 확인 창으로 처리, C-2) |
| C-2 | 포기 확인 창 구성 | 초성 힌트 미사용: "초성 힌트 보기" / "그냥 포기하기"<br>사용 후: "네, 포기합니다" (취소 버튼 없음, 바깥 클릭 / ESC로만 닫힘) | 초성 힌트 미사용: B-2와 동일<br>사용 후: "계속 도전하기" / "포기하기"<br>공통: 창 닫기(X / 바깥 클릭 / ESC) = 아무것도 안 하고 계속 플레이. 계속 플레이 쪽이 기본 선택, "포기하기"는 위험 동작 스타일로 구분. 포기 결과(C-5)를 창에 명시 (예: "포기하면 정답이 공개되고, 이후 입력하는 단어는 오늘 기록에 반영되지 않아요") |
| C-3 | 포기 버튼을 누를 수 없을 때 안내 문구 | 게임 종료(정답 / 포기) 시 버튼 비활성. 비활성 버튼은 클릭 이벤트가 발생하지 않아 "힌트를 먼저 사용해보세요!" 툴팁은 실제로 뜨지 않음 (죽은 코드) | 게임 종료 외에는 비활성 조건 없음 → 안내 문구 불필요. 툴팁 코드 제거 |
| C-4 | 포기 시 기록할 시도 횟수: 입력 횟수 그대로 / +1 | 입력 N번 후 포기 시 두 값이 다름<br>- `solvedAttempts` = N → 결과 창 "N번 시도 후 포기", 친구 비교 바<br>- `correctAttempts`(포기 시 추가되는 정답 행의 attempt) = N+1 → 공유 링크 `shared_attempts`, Amplitude 설문·공유 이벤트<br>→ 내 결과는 N, 친구가 받는 링크는 N+1 | **입력 횟수 그대로(N)로 통일.** 포기는 입력이 아니므로 +1 하지 않음 (포기 시 추가되는 정답 행 attempt도 N). 공유 관련은 `docs/todo/share.md` |
| C-5 | 포기 후 단어 입력 허용 여부 (허용 시 정답을 맞혀도 포기로 기록할지) | **입력 가능** — `GameForm`이 `gameCompleted`를 받지만 사용하지 않음. 정답을 맞혀도 `solvedAttempts` 유지, 축하 효과 없음 | **입력 허용 유지, 기록만 고정.** 포기 이후 입력은 서버 통계(제출 횟수·성공 여부)에 반영되지 않음. D-1과 동일한 "게임 종료 후 자유 탐색" 정책<br>포기 후 정답 단어 입력: 포기 시 정답 행이 목록에 추가되므로 이미 제출한 단어로 처리 (현재 동작 유지) |
