# 공지 규칙

공지 데이터와 종류, 메인 띠·`/notices`에서 보이는 방식. 색은 `docs/tasks/ui/color.md`.

## 데이터

- 위치: `src/static/notifications.ts` (정적, 배포해야 반영)
- 필드

| 필드 | 규칙 |
| --- | --- |
| `id` | 숫자 문자열, 새 공지마다 1씩 늘린다. 읽음 처리 기준이라 **기존 공지의 `id`는 바꾸거나 재사용하지 않는다** |
| `date` | KST `YYYY-MM-DD`. 보통 올리는 날. 지난 일을 기록용으로 남길 때는 그 날짜로 써도 된다 (최신순 정렬에서 밀려 메인 띠에는 안 뜸, 예: id 7) |
| `title` | 한 줄. 메인 띠에서는 길면 말줄임 |
| `content` | 본문. 줄바꿈은 `\n` |
| `type` | 아래 종류 중 하나 |

## 종류

| `type` | `/notices` 라벨 | 메인 띠 라벨 | 언제 쓰나 | 예 |
| --- | --- | --- | --- | --- |
| `update` | 업데이트 | 업데이트 | 기능 추가·변경, 개선, 버그 수정(장애 수준이 아닌 것) | 정답 초성 힌트 제공, 모바일 사용성 개선 |
| `notice` | 공지 | 공지 | 업데이트도 장애도 아닌 운영 안내 | 이용약관·개인정보처리방침 변경, 예정된 점검, 서비스 변경 안내 |
| `incident` | 장애 | 안내 | 플레이에 영향을 준 장애·버그와 그 사과, 긴급 점검 | 포기하기 버튼 버그 수정 및 사과문 |

- 애매하면: 사용자가 불편을 겪었고 그에 대한 설명·사과가 필요하면 `incident`, 아니면 `update` 또는 `notice`
- 메인 띠에서만 `incident`를 "안내"로 부드럽게 쓴다. 띠 자체가 눈에 띄게 달라져서 따로 알 수 있고, `/notices`는 기록이라 "공지"와 확실히 구분되는 "장애"로 쓴다
- `event`(이벤트)는 쓸 일이 없어 없앴다. 필요해지면 다시 추가
- 라벨은 `src/utils/notifications.ts`의 `getTypeLabel`(목록), `getBannerLabel`(띠)

## 작성 규칙

지금까지 올린 공지(`src/static/notifications.ts`)를 바탕으로 정리.

공통
- 인사말("안녕하세요, 운영자입니다")은 쓰지 않고 첫 문장부터 본론
- 유저 입장에서 바뀐 것·겪은 것만 쓴다. 서버·배포·스케줄러 같은 내부 구조나 기술 용어는 빼고, 필요하면 "매일 새 문제를 등록하는 과정"처럼 풀어 쓴다
- 기능을 어디서 쓰는지 알려줄 게 있으면 위치를 적는다 (예: "우측 상단 설정 버튼에서")
- 하지 않은 일을 약속하지 않는다. 재발 방지는 실제로 한 조치만, 내용은 간단히

제목
- 짧은 명사구, 띠에서 한 줄에 보이게 (예: "정답 초성 힌트 제공", "힌트·포기하기 개선")
- 장애는 `기간 + 무엇 + 안내 및 사과` (예: "10월 29~30일 게임 오류 안내 및 사과")

말투
- `update`, `notice`: 해요체, 한두 문장 (예: "포기하기를 누르면 초성 힌트를 받고 계속 도전할 수도 있어요")
- `incident`: 합니다체

`incident` 본문 순서
1. 무슨 일이 있었는지(기간, 유저가 겪은 증상) + 사과
2. 원인 (유저가 이해할 수 있는 수준으로)
3. 지금 상태 (해결됨, 재발하지 않게 고쳤는지)
4. 마무리 사과: "다시 한번 불편을 드려 죄송합니다."

예: id 7

## 보이는 곳

- `/notices`: 전체 공지, 최신순 (`date` 내림차순, 같은 날짜는 `id` 내림차순)
- 메인(classic) 맨 위 띠: 최신 공지 하나를 안 읽었을 때만. 누르면 `/notices`
- 설정 메뉴의 "공지사항" 링크로 `/notices` 진입

## 읽음

- 마지막으로 본 공지 `id`를 저장(`newmantle_last_seen_notification_id`)하고, 최신 공지 `id`가 더 크면 안 읽음
- 읽음 처리: `/notices` 방문, 띠 닫기(X). 메인 방문만으로는 읽음 처리하지 않는다
- 저장값이 없을 때의 처리 등 자세한 내용: `docs/tasks/ui/notices.md` 3장
