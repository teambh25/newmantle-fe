# 검증: 힌트 / 포기 규칙 테스트 케이스

## 원칙

- 기준: `docs/spec/hint-giveup.md`(이하 spec)의 **변경사항** 열. 구현 기록(`implementation.md`)을 보고 케이스를 만들거나 바꾸지 않는다
- **기능 기준**: "어떤 상태에서 무엇을 하면 어떻게 되는가"만 적는다. 코드 위치·함수명·내부 상태 이름은 구현 후에 테스트 코드를 쓸 때 정한다
- **문구는 검증하지 않는다**: 버튼·안내·토스트는 "있는지 / 없는지 / 어떤 선택지인지"만 확인한다
- 테스트 이름 앞에 케이스 ID를 붙인다 (예: `A-5-1: 999부터 15회 만에 20위에 도달`)
- 범위 밖: 테마 차이, 시각적 스타일, 서버 내부 동작(통계 반영 등)

## 검증 레벨

| 레벨 | 도구 | 대상 |
|---|---|---|
| **로직** | vitest | 화면 없이 확인 가능한 계산과 상태 변화: 힌트 순위 공식, 최고 순위 계산, 시도 횟수, 게임 상태 저장/복원, 요청 잠금, 이벤트 속성 |
| **화면** | vitest + React Testing Library + user-event | 사용자 조작으로만 드러나는 것: 버튼 활성/비활성, 확인 창 구성과 선택지, 창 닫기, 기본 포커스, 버튼 간 상호작용, 공유 링크 |

같은 규칙을 두 레벨에서 다 검증하지 않는다. 로직에서 확인한 규칙은 화면에서 "버튼에 반영되는지"만 본다.

## mock 정책

외부와 통신하거나 외부 서비스에 기록하는 것만 mock한다. 앱 내부 코드(훅, 컴포넌트, UI 라이브러리)는 실제 코드를 쓴다.

| 대상 | mock 방식 | 테스트에서 하는 일 |
|---|---|---|
| **게임 서버 API** (guess / hint / give-up) | 가짜 응답 | 성공 응답 / 실패 응답 / **응답 대기**(직접 응답시키기 전까지 대기) 세 가지 모드. 요청된 경로·순위·횟수를 기록해 검증 |
| **Supabase** | 가짜 클라이언트 | 로그인 세션 없음 (게스트)으로 고정. 공유 링크 생성 시 필요 |
| **Amplitude** | 이벤트 기록 spy | 이벤트 이름·속성 검증 (E-1) |
| **축하 효과** (confetti) | 호출 spy | 화면에서 확인할 수 없으므로 호출 여부만 검증 (C-5) |
| **클립보드 / 공유** (`navigator.clipboard`, `navigator.share`) | 클립보드 spy, 공유 API 없음 | 공유 링크 내용 검증 (C-4) |
| **시간** | 날짜 고정 | 하루 단위 저장 상태가 테스트 실행 날짜에 따라 달라지지 않게 |

## 사전 상태 프리셋

여러 케이스에서 재사용하는 시작 상태. "입력"은 사용자가 제출한 단어, "힌트"는 일반 힌트로 받은 단어다.

| 프리셋 | 상태 |
|---|---|
| `EMPTY` | 아무것도 없음 |
| `OUT_ONLY` | 순위 밖(-1) 입력 2개 |
| `TOP(n)` | 최고 순위 n위 입력 1개 (+ 순위 밖 입력 1개) |
| `CONSONANT_USED` | 초성 힌트 사용, 그 외 없음 |
| `SOLVED(k)` | k번째 입력에 정답 |
| `GIVEN_UP(n)` | 입력 n개 후 포기 |
