# 검증: 규칙 페이지 / 첫 방문 모달

## 원칙

- 기준: `plan.md`의 모달 규칙(M-*)과 진입점, `docs/spec/rules.md`. 구현을 보고 케이스를 만들거나 바꾸지 않는다
- **문구는 검증하지 않는다**: 규칙 내용·모달 문구·placeholder는 "있는지 / 어디로 가는지"만 자동으로 보고, 내용은 수동으로 확인한다
- 요소는 role과 접근 가능한 이름으로 찾는다
- 테스트 이름 앞에 케이스 ID를 붙인다 (예: `M-1-1: 첫 방문 시 안내 모달이 열림`)
- 범위 밖: excel 테마(M-5 제외), 시각적 스타일

## 검증 레벨

| 레벨 | 도구 | 대상 |
| --- | --- | --- |
| **화면** | vitest + React Testing Library + user-event | 모달 열림/닫힘과 저장 값, 말풍선 순서, 링크 위치(`href`), 도움말 제거 |
| **수동** | 브라우저 (데스크톱 + 모바일) | 문구, 레이아웃, 모바일 겹침, 키보드 |

이번 작업은 계산 로직이 없어서 로직 레벨 케이스는 없다.

## mock 정책

`src/test/README.md`와 같다. 이번 작업에서 쓰는 것만 적는다.

| 대상 | 방식 | 비고 |
| --- | --- | --- |
| Supabase | 가짜 클라이언트 | 기본 비로그인. M-6-3만 로그인 세션 |
| 게임 서버 | 가짜 `fetch` | 메인 렌더링에 필요한 만큼 |
| `localStorage` | 실제 (jsdom) | 모달 확인 여부 / `login-tooltip-dismissed` / `newmantle_game_data`로 사전 상태 구성 |

- 메인 화면 전체(헤더·모달·푸터)를 렌더링해야 한다. 화면 하네스에 없으면 추가
