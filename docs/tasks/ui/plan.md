출처: `docs/todo/ui.md`. 범위는 classic 테마의 메인(`/`)·통계(`/stats`) 헤더와 메인 공지사항.

입력 단어 목록(순위 색, 방금 입력·힌트 단어 강조, 초성, 보이는 개수)은 별도 문서: `word-list.md`

## 1. 헤더 넘침 → 로그아웃을 설정 메뉴로 (후보 B)

### 결정

- 헤더의 계정 영역
  - 비로그인: 로그인 버튼 (그대로)
  - 로그인: 닉네임만 보여준다. 로그아웃 버튼은 헤더에서 뺀다
  - 닉네임은 최대 폭 7rem(112px)에서 말줄임. 전체 닉네임은 `title`로 확인
- 설정 메뉴
  - 로그인 상태면 맨 아래 "계정" 영역에 로그아웃 버튼을 둔다. 비로그인이면 영역 자체가 없다
  - 로그아웃 동작은 기존과 같다 (`supabase.auth.signOut()` 후 새로고침)
  - 회원 탈퇴 진입점도 나중에 이 영역에 붙인다 (`docs/tasks/withdrawal/plan.md`)
- excel 테마도 같은 `AuthButton` / `SettingsButton`을 써서 함께 바뀐다. 로그아웃이 헤더에서 빠지므로 excel 설정 메뉴에도 로그아웃이 있어야 한다

### 작은 화면 보정 (sm 미만)

B만으로는 비로그인 상태도 넘친다 (ui.md 계산: 비로그인 약 384px > 343px). 그래서 작은 화면에서만 아래를 함께 적용한다.

- 부제 "단어 추측 게임" 숨김 (`hidden sm:block`)
- 오른쪽 아이콘 간격 16px → 8px (`space-x-2 sm:space-x-4`)
- 로고·부제 줄바꿈 방지 (`whitespace-nowrap`), 오른쪽 영역은 줄어들지 않게 (`shrink-0`)
- `/stats` 헤더도 간격을 같이 줄인다

대략 폭 (375px, 사용 가능 약 343px)

| 상태 | 왼쪽 | 오른쪽 | 합계 |
| --- | --- | --- | --- |
| 비로그인 | 로고 약 72 | 로그인 56 + 아이콘 3개 96 + 간격 24 = 176 | 약 248 |
| 로그인 (긴 닉네임) | 약 72 | 닉네임 최대 112 + 96 + 24 = 232 | 약 304 |

## 3. 입력창 위 게임 날짜에 요일 추가, 검정색으로

목적: 어제 문제를 풀고 있을 때 오늘 문제가 아니라는 걸 알아채게 한다.

- 형식: `11월 11일` → `11월 11일 (수)`
- 요일은 게임 날짜(KST `YYYY-MM-DD`)의 달력 요일. 기기 타임존과 무관해야 한다 (LA 기기에서도 KST 11/11이면 수요일)
- 색: `text-gray-400` → `text-gray-900`. 크기(`text-xs`)·굵기는 그대로
- 범위: classic. excel의 시트 이름(`Sheet: 11월 11일`)은 그대로

## 4. 입력창: 제출 버튼 제거, 힌트·포기 글씨 버튼

모바일은 마우스를 올리는 동작이 없어 툴팁이 안 뜨고, 아이콘만으로는 무슨 버튼인지 모른다. 또 PC·모바일 모두 엔터로 연속 입력하는 게 편해서 큰 "제출" 버튼은 없앤다.

- "제출" 글씨 버튼을 없애고, 입력창 안 오른쪽 끝에 엔터 아이콘 버튼(접근 가능한 이름 `제출`)만 둔다. 제출 잠금 규칙(`hint-giveup.md` D-2)은 이 버튼에 그대로 적용
- 힌트·포기는 엔터 아이콘 왼쪽, 입력창 안에 아이콘 + 글씨 버튼(`힌트`, `포기`)으로 둔다. 크기는 모바일(sm 미만)만 작게: 글씨 `text-xs`·아이콘 14px·엔터 28px, PC는 `text-sm`·16px·32px. 글씨만 두면 두 버튼 경계가 안 보여서 아이콘으로 구분. 엔터 아이콘과 사이에 얇은 구분선
- 색: 모두 검정(`text-gray-900`). 초록은 정답 표시 색과 겹치고, 빨강은 포기를 눈에 띄게 만들어 초성 힌트로 계속 도전하게 하려는 의도(`hint-giveup.md` B)와 반대라 쓰지 않는다
- 글씨가 보이므로 툴팁은 뺀다. 동작·비활성 규칙은 그대로
- 엔터 안내
  - 모바일 키보드 엔터 키를 "보내기"로 (`enterKeyHint="send"`)
  - placeholder: 항상 "단어 입력 후 엔터". 에러 문구가 있으면 에러 문구 우선 (기존과 같음)
  - 처음 전용 문구("아무 단어나 ...")는 버튼 영역이 넓어져 들어가지 않아 없앤다. 첫 입력 유도는 첫 방문 안내 모달이 맡는다
- 폭 (375px, 입력창 약 343px): 오른쪽 버튼 영역 약 145px (힌트·포기 각 약 52 + 구분선 + 엔터 28), 입력 영역 약 180px. placeholder 약 124px라 320px 기기에서도 들어감
- 경과: 입력창 아래 오른쪽 → 단어 목록 오른쪽 위 → 입력창 안(현재)
- 범위: classic

## 5. 로그인 유저에게 통계 페이지 유도 말풍선 (최초 1회)

비로그인 유저에게 로그인 말풍선("비로그인은 기록이 날아가요")을 띄우듯, 로그인 유저에게는 통계 페이지를 알려준다.

- 대상: 로그인 유저, 메인(classic) 헤더의 통계 아이콘 아래
- 문구 예: "내 정답 기록을 볼 수 있어요"
- 모양·닫기는 로그인 말풍선과 같다: 말풍선 클릭 또는 X 버튼으로 닫고, 닫으면 다시 안 뜬다 (`localStorage` `stats-tooltip-dismissed`)
- 통계 페이지(`/stats`)에 한 번 들어가면 안내가 필요 없으므로 같은 키를 저장한다
- 첫 방문 안내 모달이 열려 있는 동안은 숨기고, 닫힌 뒤에 보인다 (로그인 말풍선의 M-6과 같음)
- 비로그인 유저에게는 로그인 말풍선만, 로그인 유저에게는 통계 말풍선만 뜬다 (동시에 뜨지 않음)

## 7. 첫 입력 유도 말풍선, 말풍선 순서

placeholder를 "단어 입력 후 엔터"로 줄이면서 빠진 첫 입력 유도("아무 단어나")를 말풍선으로 맡긴다. 말풍선이 여러 개 동시에 뜨지 않게 순서를 정한다.

- 입력창 말풍선 "아무 단어나 입력해보세요"
  - 대상: 단어를 한 번도 입력해 본 적 없는 사람 (classic)
  - 위치: 입력창 바로 아래
  - 사라짐: 첫 단어를 제출(엔터 / 엔터 아이콘)하면. 입력창을 누르거나 글자를 치는 것만으로는 닫지 않는다 (제출까지 안내가 보이도록). 말풍선을 누르면 입력창으로 포커스만 간다. 한 번 닫히면 다시 안 뜬다 (`localStorage` `newmantle_input_tooltip_done`)
  - 빈 입력으로 엔터는 제출이 아니므로 닫지 않는다. 서버가 오류를 돌려줘도 제출은 한 것이므로 닫는다
  - 포커스로 닫지 않는 이유: 게임 화면이 진입 직후 입력창에 자동 포커스를 주는 경우(개발 서버 StrictMode에서 `useGameForm`의 첫 마운트 건너뛰기가 두 번째 effect 실행에서 풀림)가 있어, 포커스로 닫으면 사용자가 보기도 전에 닫혔다 (V-11에서 발견)
  - "한 번도 입력 안 함" 판단: 위 키가 없고, 기존 유저 흔적도 없을 때. 흔적 = 저장된 게임 기록(`newmantle_game_data`)에 단어가 있음, 또는 로그인 말풍선을 닫은 적 있음(`login-tooltip-dismissed`). 흔적이 있으면 바로 키를 저장한다
  - 기기 단위다. 다른 기기에서 처음 들어온 로그인 유저도 한 번은 본다
- 순서 (한 번에 하나)
  1. 첫 방문 안내 모달
  2. 입력창 말풍선 (해당될 때, 첫 단어 제출까지)
  3. 헤더 말풍선: 비로그인 → 로그인 말풍선, 로그인 → 통계 말풍선 (각각 최초 1회)
- 헤더 말풍선은 모달이 닫히고 입력창 말풍선이 끝난 뒤에만 보인다. 기존 유저(이미 입력해 본 사람)는 입력창 말풍선이 없으므로 모달을 닫으면 바로 헤더 말풍선 (규칙 작업 M-6과 같음)
- 로그인부터 하는 경우: 모달을 닫고 입력 없이 바로 로그인 → 돌아오면 입력창 말풍선이 그대로 있고 로그인 말풍선은 안 뜸(로그인 상태) → 첫 단어를 제출하면 통계 말풍선
- 비로그인으로 입력한 뒤 로그인하면 입력창 말풍선은 이미 끝났으므로 바로 통계 말풍선
- excel 테마는 그대로 (입력창 말풍선 없음, 로그인 말풍선은 기존대로)
- 첫 방문 모달을 닫은 뒤 포커스
  - "시작하기": 입력창에 커서를 둔다 ("이제 게임할게요"라는 뜻). iOS Safari는 탭한 순간에 포커스해야 키보드를 올려주므로, 버튼을 누른 그 처리 안에서 모달을 닫고 바로 포커스한다
  - X / ESC / 바깥 클릭: 입력창으로 보내지 않는다 ("일단 닫기"라는 뜻. 모바일에서 원치 않는 키보드가 올라와 화면을 가리지 않게). 어디에 입력할지는 입력창 말풍선이 알려준다
  - 이전에는 닫는 방법에 따라 입력창으로 가기도 하고 안 가기도 했다 (의도한 동작 없음, Radix가 열리기 전 포커스로 되돌리는 동작에 따라 달라짐). X는 그대로 둔다 (규칙 작업 M-4 유지)

## 8. 헤더 말풍선 5초 뒤 자동 닫힘, 결과 상자 로그인 안내 (2026-11-13)

입력창 위 날짜 제목을 가운데로 옮기면서(`word-list.md` 3-4), 모바일(375px)에서 로그인 말풍선이 제목을 거의 다 가리게 됐다 (V-17). 말풍선이 떠 있는 시간을 줄이고, 로그인 안내는 게임이 끝난 결과 상자에서 한 번 더 한다.

- 헤더 말풍선(로그인·통계): 보이기 시작하고 **5초** 뒤 자동으로 닫힘
  - 두 줄짜리 짧은 문구라 읽는 데 1–2초. 5초면 읽을 시간은 충분하고 오래 가리지 않음
  - 5초는 실제로 보인 순간부터 센다. 첫 방문 모달·입력창 말풍선 때문에 숨어 있는 동안은 세지 않음 (7장 순서 그대로)
  - 자동으로 닫혀도 X로 닫은 것과 같이 저장 → 다시 안 뜸. 로그인 안내는 결과 상자가 매번 하므로 말풍선은 한 번 소개로 충분. 매 방문마다 5초씩 제목을 가리지 않게
  - 게임 종료 후 띄우는 안(말풍선이 결과 상자 첫 줄을 가림)은 버림
- 결과 상자(정답 맞힘·포기) 안 로그인 안내: **비로그인만**
  - 결과 문구 아래 한 줄 + 로그인 링크(`/login`). 예: "로그인하면 오늘 맞힌 기록이 남아요" (포기는 "로그인하면 오늘 기록이 남아요")
  - 사실 확인: 로그인하면 게스트 기록이 계정으로 연결됨 (`useGuestLink` → `POST /v2/stats/link`)
  - 로그인 유저에게는 없음
