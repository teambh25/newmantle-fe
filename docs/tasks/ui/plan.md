출처: `docs/todo/ui.md`. 범위는 classic 테마의 메인(`/`)·통계(`/stats`) 헤더와 메인 공지사항.

입력 단어 목록(순위 색, 방금 입력·힌트 단어 강조, 초성, 보이는 개수)은 별도 문서: `word-list.md`

## 1. 헤더 넘침 → 로그아웃을 설정 메뉴로 (후보 B)

### 결정

- 헤더의 계정 영역
  - 비로그인: 로그인 버튼 (그대로)
  - 로그인: 닉네임만 보여준다. 로그아웃 버튼은 헤더에서 뺀다
  - 닉네임은 최대 폭 7rem(112px)에서 말줄임. 전체 닉네임은 `title`로 확인
- 설정 메뉴
  - 로그인 상태면 맨 아래 "계정" 영역에 로그아웃 버튼을 둔다. 비로그인이면 영역 자체가 없다
  - 로그아웃 동작은 기존과 같다 (`supabase.auth.signOut()` 후 새로고침)
  - 회원 탈퇴 진입점도 나중에 이 영역에 붙인다 (`docs/tasks/withdrawal/plan.md`)
- excel 테마도 같은 `AuthButton` / `SettingsButton`을 써서 함께 바뀐다. 로그아웃이 헤더에서 빠지므로 excel 설정 메뉴에도 로그아웃이 있어야 한다

### 작은 화면 보정 (sm 미만)

B만으로는 비로그인 상태도 넘친다 (ui.md 계산: 비로그인 약 384px > 343px). 그래서 작은 화면에서만 아래를 함께 적용한다.

- 부제 "단어 추측 게임" 숨김 (`hidden sm:block`)
- 오른쪽 아이콘 간격 16px → 8px (`space-x-2 sm:space-x-4`)
- 로고·부제 줄바꿈 방지 (`whitespace-nowrap`), 오른쪽 영역은 줄어들지 않게 (`shrink-0`)
- `/stats` 헤더도 간격을 같이 줄인다

대략 폭 (375px, 사용 가능 약 343px)

| 상태 | 왼쪽 | 오른쪽 | 합계 |
| --- | --- | --- | --- |
| 비로그인 | 로고 약 72 | 로그인 56 + 아이콘 3개 96 + 간격 24 = 176 | 약 248 |
| 로그인 (긴 닉네임) | 약 72 | 닉네임 최대 112 + 96 + 24 = 232 | 약 304 |

## 3. 입력창 위 게임 날짜에 요일 추가, 검정색으로

목적: 어제 문제를 풀고 있을 때 오늘 문제가 아니라는 걸 알아채게 한다.

- 형식: `11월 11일` → `11월 11일 (수)`
- 요일은 게임 날짜(KST `YYYY-MM-DD`)의 달력 요일. 기기 타임존과 무관해야 한다 (LA 기기에서도 KST 11/11이면 수요일)
- 색: `text-gray-400` → `text-gray-900`. 크기(`text-xs`)·굵기는 그대로
- 범위: classic. excel의 시트 이름(`Sheet: 11월 11일`)은 그대로

## 4. 입력창: 제출 버튼 제거, 힌트·포기 글씨 버튼

모바일은 마우스를 올리는 동작이 없어 툴팁이 안 뜨고, 아이콘만으로는 무슨 버튼인지 모른다. 또 PC·모바일 모두 엔터로 연속 입력하는 게 편해서 큰 "제출" 버튼은 없앤다.

- "제출" 글씨 버튼을 없애고, 입력창 안 오른쪽 끝에 엔터 아이콘 버튼(접근 가능한 이름 `제출`)만 둔다. 제출 잠금 규칙(`hint-giveup.md` D-2)은 이 버튼에 그대로 적용
- 힌트·포기는 엔터 아이콘 왼쪽, 입력창 안에 아이콘 + 글씨 버튼(`힌트`, `포기`)으로 둔다. 크기는 모바일(sm 미만)만 작게: 글씨 `text-xs`·아이콘 14px·엔터 28px, PC는 `text-sm`·16px·32px. 글씨만 두면 두 버튼 경계가 안 보여서 아이콘으로 구분. 엔터 아이콘과 사이에 얇은 구분선
- 색: 모두 검정(`text-gray-900`). 초록은 정답 표시 색과 겹치고, 빨강은 포기를 눈에 띄게 만들어 초성 힌트로 계속 도전하게 하려는 의도(`hint-giveup.md` B)와 반대라 쓰지 않는다
- 글씨가 보이므로 툴팁은 뺀다. 동작·비활성 규칙은 그대로
- 엔터 안내
  - 모바일 키보드 엔터 키를 "보내기"로 (`enterKeyHint="send"`)
  - placeholder: 항상 "단어 입력 후 엔터". 에러 문구가 있으면 에러 문구 우선 (기존과 같음)
  - 처음 전용 문구("아무 단어나 ...")는 버튼 영역이 넓어져 들어가지 않아 없앤다. 첫 입력 유도는 첫 방문 안내 모달이 맡는다
- 폭 (375px, 입력창 약 343px): 오른쪽 버튼 영역 약 145px (힌트·포기 각 약 52 + 구분선 + 엔터 28), 입력 영역 약 180px. placeholder 약 124px라 320px 기기에서도 들어감
- 경과: 입력창 아래 오른쪽 → 단어 목록 오른쪽 위 → 입력창 안(현재)
- PC(sm 이상)는 입력창 폭을 최대 **420px**로 줄여 가운데에 둔다 (2026-11-13). 672px 전체를 쓰면 글자 칸 대부분이 비어 입력이 왼쪽에 쏠려 보임. 420 = 왼쪽 여백 12 + 가장 긴 안내 문구 약 212 (9장 3차) + 간격 약 16 + 버튼 영역 176. 모바일은 화면 폭 그대로 (이미 거의 전체 폭이라 줄이면 아래 표와 들쭉날쭉)
  - 입력창만 줄이니 아래 단어 목록이 넓어 어색하고, 목록도 단어 칸 공백이 컸음 → 게임 영역(결과 상자·단어 목록)을 **480px**로, 입력창은 그보다 조금 좁은 420px로 둔다 (목록이 입력창보다 약간 넓은 편이 자연스러움). 단어 칸은 약 224px. 헤더·공지는 그대로
  - (한때 영역 전체를 420px로 맞췄으나 목록이 입력창과 똑같아 답답해 보여 480px로)
- 모바일(sm 미만)은 엔터 아이콘과 구분선을 숨긴다 (2026-11-13). 버튼 영역이 입력창의 40% 넘게 차지해 글자 칸이 왼쪽에 몰려 보이고, 포기가 엔터 옆에 붙어 있었음. 모바일은 키보드 "보내기" 키·placeholder·첫 방문 안내로 엔터 제출을 알 수 있다. PC는 자리가 넉넉하고 마우스로 누를 버튼이 있는 편이 나아 그대로
- 범위: classic

## 5. 로그인 유저에게 통계 페이지 유도 말풍선 (최초 1회)

비로그인 유저에게 로그인 말풍선("비로그인은 기록이 날아가요")을 띄우듯, 로그인 유저에게는 통계 페이지를 알려준다.

- 대상: 로그인 유저, 메인(classic) 헤더의 통계 아이콘 아래
- 문구 예: "내 정답 기록을 볼 수 있어요"
- 모양·닫기는 로그인 말풍선과 같다: 말풍선 클릭 또는 X 버튼으로 닫고, 닫으면 다시 안 뜬다 (`localStorage` `stats-tooltip-dismissed`)
- 통계 페이지(`/stats`)에 한 번 들어가면 안내가 필요 없으므로 같은 키를 저장한다
- 첫 방문 안내 모달이 열려 있는 동안은 숨기고, 닫힌 뒤에 보인다 (로그인 말풍선의 M-6과 같음)
- 비로그인 유저에게는 로그인 말풍선만, 로그인 유저에게는 통계 말풍선만 뜬다 (동시에 뜨지 않음)

## 7. 첫 입력 유도 말풍선, 말풍선 순서

placeholder를 "단어 입력 후 엔터"로 줄이면서 빠진 첫 입력 유도("아무 단어나")를 말풍선으로 맡긴다. 말풍선이 여러 개 동시에 뜨지 않게 순서를 정한다.

- 입력창 말풍선 "아무 단어나 입력해보세요"
  - 대상: 단어를 한 번도 입력해 본 적 없는 사람 (classic)
  - 위치: 입력창 바로 아래
  - 사라짐: 첫 단어를 제출(엔터 / 엔터 아이콘)하면. 입력창을 누르거나 글자를 치는 것만으로는 닫지 않는다 (제출까지 안내가 보이도록). 말풍선을 누르면 입력창으로 포커스만 간다. 한 번 닫히면 다시 안 뜬다 (`localStorage` `newmantle_input_tooltip_done`)
  - 빈 입력으로 엔터는 제출이 아니므로 닫지 않는다. 서버가 오류를 돌려줘도 제출은 한 것이므로 닫는다
  - 포커스로 닫지 않는 이유: 게임 화면이 진입 직후 입력창에 자동 포커스를 주는 경우(개발 서버 StrictMode에서 `useGameForm`의 첫 마운트 건너뛰기가 두 번째 effect 실행에서 풀림)가 있어, 포커스로 닫으면 사용자가 보기도 전에 닫혔다 (V-11에서 발견)
  - "한 번도 입력 안 함" 판단: 위 키가 없고, 기존 유저 흔적도 없을 때. 흔적 = 저장된 게임 기록(`newmantle_game_data`)에 단어가 있음, 또는 로그인 말풍선을 닫은 적 있음(`login-tooltip-dismissed`). 흔적이 있으면 바로 키를 저장한다
  - 기기 단위다. 다른 기기에서 처음 들어온 로그인 유저도 한 번은 본다
- 순서 (한 번에 하나)
  1. 첫 방문 안내 모달
  2. 입력창 말풍선 (해당될 때, 첫 단어 제출까지)
  3. 헤더 말풍선: 비로그인 → 로그인 말풍선, 로그인 → 통계 말풍선 (각각 최초 1회)
- 헤더 말풍선은 모달이 닫히고 입력창 말풍선이 끝난 뒤에만 보인다. 기존 유저(이미 입력해 본 사람)는 입력창 말풍선이 없으므로 모달을 닫으면 바로 헤더 말풍선 (규칙 작업 M-6과 같음)
- 로그인부터 하는 경우: 모달을 닫고 입력 없이 바로 로그인 → 돌아오면 입력창 말풍선이 그대로 있고 로그인 말풍선은 안 뜸(로그인 상태) → 첫 단어를 제출하면 통계 말풍선
- 비로그인으로 입력한 뒤 로그인하면 입력창 말풍선은 이미 끝났으므로 바로 통계 말풍선
- excel 테마는 그대로 (입력창 말풍선 없음, 로그인 말풍선은 기존대로)
- 첫 방문 모달을 닫은 뒤 포커스
  - "시작하기": 입력창에 커서를 둔다 ("이제 게임할게요"라는 뜻). iOS Safari는 탭한 순간에 포커스해야 키보드를 올려주므로, 버튼을 누른 그 처리 안에서 모달을 닫고 바로 포커스한다
  - X / ESC / 바깥 클릭: 입력창으로 보내지 않는다 ("일단 닫기"라는 뜻. 모바일에서 원치 않는 키보드가 올라와 화면을 가리지 않게). 어디에 입력할지는 입력창 말풍선이 알려준다
  - 이전에는 닫는 방법에 따라 입력창으로 가기도 하고 안 가기도 했다 (의도한 동작 없음, Radix가 열리기 전 포커스로 되돌리는 동작에 따라 달라짐). X는 그대로 둔다 (규칙 작업 M-4 유지)

## 8. 헤더 말풍선 5초 뒤 자동 닫힘, 결과 상자 로그인 안내 (2026-11-13)

입력창 위 날짜 제목을 가운데로 옮기면서(`word-list.md` 3-4), 모바일(375px)에서 로그인 말풍선이 제목을 거의 다 가리게 됐다 (V-17). 말풍선이 떠 있는 시간을 줄이고, 로그인 안내는 게임이 끝난 결과 상자에서 한 번 더 한다.

- 헤더 말풍선(로그인·통계): 보이기 시작하고 **5초** 뒤 자동으로 닫힘
  - 두 줄짜리 짧은 문구라 읽는 데 1–2초. 5초면 읽을 시간은 충분하고 오래 가리지 않음
  - 5초는 실제로 보인 순간부터 센다. 첫 방문 모달·입력창 말풍선 때문에 숨어 있는 동안은 세지 않음 (7장 순서 그대로)
  - 자동으로 닫혀도 X로 닫은 것과 같이 저장 → 다시 안 뜸. 로그인 안내는 결과 상자가 매번 하므로 말풍선은 한 번 소개로 충분. 매 방문마다 5초씩 제목을 가리지 않게
  - 게임 종료 후 띄우는 안(말풍선이 결과 상자 첫 줄을 가림)은 버림
- 결과 상자(정답 맞힘·포기) 안 로그인 안내: **비로그인만**
  - 결과 문구 아래 한 줄 + 로그인 링크(`/login`). 예: "로그인하면 오늘 맞힌 기록이 남아요" (포기는 "로그인하면 오늘 기록이 남아요")
  - 사실 확인: 로그인하면 게스트 기록이 계정으로 연결됨 (`useGuestLink` → `POST /v2/stats/link`)
  - 로그인 유저에게는 없음
  - → 링크는 빼고 문구만 남김 (헤더에 로그인 버튼이 있음, `result-box.md` 5)

## 9. 없는 단어 안내: 입력창 빨간 테두리 (2026-11-13)

- 지금은 입력창 placeholder에 "없는 단어입니다"만 떠서 눈에 잘 안 띔
- 알림창은 쓰지 않음: 자주 나오는 가벼운 실수라 흐름이 끊기고, 모바일에서 키보드가 내려감
- 1차: 입력창 테두리를 빨갛게 (placeholder 문구는 그대로 빨간 글씨). 다음 제출 때 풀림. 써 보고 부족하면 입력창 아래 빨간 말풍선(단어·이유 포함) 검토
- 2차: 문구에 입력한 단어를 넣음: "'사랑해'는 없는 단어예요". 조사 은/는은 마지막 글자 받침으로 고름 (한글이 아니면 "은(는)"). 글자색은 테두리와 같은 빨강
- 3차: 문구 속 단어가 6글자를 넘으면 앞 5글자 + "…"로 줄인다 ("'가나다라마…'는 없는 단어예요"). 조사는 원래 단어 마지막 글자로 고른다. 가장 긴 문구가 약 212px(16px 글꼴)로 고정돼 아래 입력창 폭을 줄일 수 있다
  - 360px 폰에서는 글자 칸이 약 204px라 그래도 끝이 잘림 → 잘리는 대로 두되 끝을 "…"로 (`text-overflow: ellipsis`, Chrome 확인). 6글자 넘는 없는 단어는 드물다
  - (한때 모바일 안내 문구를 14px로 줄여 들어가게 했으나, 글자가 작아져 오히려 공백이 많아 보여 되돌림)
- 4차: 작은 폰에서는 끝의 "…"도 잘려 안 보임 → 문구를 줄여 "'사랑'은 없는 단어"로 ("예요"를 뺌, 가장 긴 문구 약 182px). 단어 6글자 초과 말줄임과 입력창 끝 말줄임은 그대로
- 테두리만 빨가면 안의 힌트·포기·엔터 버튼은 그대로라 어색함 → 입력창 배경도 옅은 빨강(`bg-red-50`). 꽉 찬 빨강은 과하고 글씨가 안 보여 쓰지 않음
- 5차: 안내를 입력창 안(placeholder)이 아니라 **입력창 아래**에 둔다. 2~4차의 문구 길이·말줄임·배경 문제가 모두 사라짐
  - 없는 단어를 내면 입력한 단어를 지우지 않고 남긴다. 오타면 고쳐서 바로 다시 내면 된다
  - 입력창 테두리 빨강 + 아래에 경고 아이콘(`CircleAlert`)과 "게임에 등록되지 않은 단어예요" (빨간 작은 글씨: 모바일 11px, PC 12px). 단어를 문구에 넣지 않으므로 조사·말줄임 함수는 없앰
  - 입력창과 단어 목록 사이 여백에 겹쳐 띄워 목록이 밀리지 않게

  - 옅은 빨간 배경은 뺌 (아래 경고가 이유를 알려 주므로). 다시 넣어 비교해 봤으나 빼는 쪽으로 결정
  - placeholder는 늘 "단어 입력 후 엔터"
  - excel 테마는 그대로 (입력을 지우고 placeholder에 안내)
- 6차 (11장 이후, 12장에서 주 안내는 단어 목록으로 옮김): 없는 단어를 내면 입력창을 **비우고**, 안내를 다시 **placeholder**에 띄운다
  - 없는 단어는 오타보다 게임 사전에 없는 경우가 많아 보임. 남기면 매번 지우고 다시 쳐야 하고, 오타라도 몇 글자라 다시 치는 수고가 작다 (없는 단어 이유를 따로 기록하는 데이터는 없음)
  - 비우면 무엇을 쳤는지 사라지므로 문구에 단어를 다시 넣는다. 조사·단어 줄이기 함수(`utils/korean`)를 되살림: 6글자를 넘으면 앞 5글자 + "…", 문구는 4차처럼 짧게. 입력창 끝 CSS 말줄임은 넣지 않는다 (말줄임이 두 번 들어가 어색함). 엔터 아이콘을 빼며 모바일 글자 칸이 넓어져 계산상 360px 폰에서도 들어감
  - 보이는 모습: 빨간 테두리 + 빨간 글씨, 빨간 테두리 + 검정 글씨, 빨간 글씨만, 검정 글씨만을 차례로 써 봄 → 12장에서 평소 placeholder 색으로
  - 처음엔 11장의 노란 2px 테두리 + 진회색 글씨로 했으나 노랑이 디자인에 안 어울림. 회색 테두리는 평소 테두리(옅은 회색)와 구분이 안 되고, 회색 배경은 제출 중 잠긴 입력창처럼 보여 뺌 → 입력창 표시(빨간 테두리)는 없는 단어에만, 요청 실패는 아래 문구만으로 나눔
  - placeholder는 스크린리더가 바로 읽지 않으므로 같은 안내를 화면에 안 보이는 알림(`role="alert"`, `sr-only`)으로도 둔다
  - 요청 실패(11장)는 입력창 아래 그대로. 나누는 기준: 내가 친 단어가 문제면 입력창 안, 기능이 고장 나면 입력창 아래. 안내는 한 번에 하나: 없는 단어 안내 중 요청이 실패하면 없는 단어 표시를 풀고 아래 빨간 안내만

## 12. 없는 단어·제출 실패는 단어 목록 맨 위에 (2026-11-13)

- 플레이 습관: 단어를 내고 입력창이 아니라 단어 목록 맨 위(방금 낸 단어의 순위·유사도)를 보며 다음 단어를 친다. 그래서 제출 결과 안내는 입력창보다 목록 맨 위가 눈에 띈다. 제출 중 스피너 줄도 같은 자리
- (2026-11-13 이후: 굵은 구분선 대신 표를 **방금 입력 칸**과 **기록 표**로 나눔, `word-list.md` 3-2. 이 장의 "구분선 위"는 방금 입력 칸, "구분선 아래·순위 자리"는 기록 표)
- 없는 단어·단어 제출 실패를 목록 맨 위 **방금 입력 줄**(굵은 구분선 위) 자리에 **임시 줄**로 띄운다. 구분선 위는 늘 직전에 입력한 것
  - 새 줄을 하나 더 얹지 않는다. 원래 맨 위에 있던 직전 단어는 구분선 아래 순위 순서 자리로 내려간다
  - 모양은 보통 줄과 같다 (배경을 바꾸지 않음). 보통 줄처럼 4칸이고, 순위·유사도 칸에 숫자 대신 상태를 적는다 (없는 단어는 둘 다 "없다"는 표시, 제출 실패는 둘 다 오류 표시. 초성·정답은 순위 칸에 그 종류, 유사도 칸에 100). 처음엔 두 칸을 합쳐 안내 하나만 적었으나, 글자가 다른 줄의 순위·유사도 위치와 안 맞아 줄 모양이 달라 보여 나눔. 번호 칸은 시도 횟수에 안 들어가므로 표시(없는 단어 "-" 글자, 제출 실패 `CircleAlert`, 보통 글씨 색. 금지 `Ban`은 뜻이 너무 세고, `Minus` 아이콘은 너무 커서 "-" 글자로 되돌림), 단어 칸은 친 단어 그대로(긴 단어는 표처럼 끝 "…")
  - (처음엔 스피너 줄처럼 회색 줄을 맨 위에 하나 더 얹었으나, 구분선 위가 직전 입력이 아니게 돼 바꿈)
  - 저장하지 않는다 (localStorage·통계에 안 남음, 새로고침하면 사라짐). 같은 없는 단어를 다시 내도 막지 않고 임시 줄을 다시 띄운다: 서버가 404로 답하고 시도 횟수에 안 들어가 손해가 없고, 저장해 봐야 정렬 때문에 목록 맨 아래라 거의 안 보임
  - 보이는 줄 수는 그대로 7줄이라 임시 줄이 한 자리를 차지하면, 단어가 7개뿐이어도 "더보기"가 나온다 (안 그러면 7번째 단어를 볼 방법이 없음)
  - 사라지는 때: 구분선 위에 다른 줄이 올라올 때 (다음 제출, 이미 낸 단어를 다시 내 맨 위로 올라올 때, 힌트·초성·포기). 구분선 위는 늘 가장 최근 항목이고 초성·정답도 그 자리에 한 줄로 보인다 (`word-list.md` 3-2). 다음 단어도 없는 단어거나 실패면 내용만 바뀜. 입력창에 글자를 쳐도 남는다 (다음 단어를 고르는 동안 볼 수 있게)
  - 보이는 줄 수는 스피너 줄처럼 임시 줄 포함 그대로 7줄
- 이미 제출한 단어: 지금처럼 서버에 요청하지 않고 그 줄을 맨 위(구분선 위)로 올리되, 번호 칸에 반복 아이콘(`Repeat`, 보통 글씨 색)을 번호 대신 둔다
  - "아까 냈던 거네"를 알아채게 해 몰입을 돕고, 시도 횟수가 늘었나 하는 걱정을 던다. 순위·유사도는 진짜 정보라 그대로
  - 아이콘 색은 번호와 같은 보통 글씨 색 (처음엔 연회색이었으나 번호 자리라 흐리면 비활성처럼 보임). 힌트 줄 # 칸도 "힌트" 글자 대신 갈색 전구 아이콘으로 맞춤 (`word-list.md` 3-3)
  - 번호 칸은 힌트 줄이 이미 줄 종류를 알리는 자리라 같은 방식. 단어 옆 글자는 좁은 폰에서 긴 단어와 자리를 다퉈 뺌. 아이콘만 두고 번호는 숨김
  - 임시 줄처럼 구분선 위에 다음 줄(입력·힌트·초성·정답)이 올라오면 원래 번호로 돌아가고 저장하지 않는다. 스크린리더는 아이콘 이름("이미 입력한 단어")으로 읽음
- 입력창 쪽
  - 없는 단어: 입력창을 비움. placeholder 안내(단어 포함)는 혹시 입력창을 보는 사람을 위해 남기되 글씨는 평소 placeholder 색. 테두리·배경 없음. 안 보이는 알림(`sr-only`)도 그대로
  - 단어 제출 실패: 단어를 남기고(엔터로 재시도) 입력창을 막는 느낌으로 빨간 테두리 + 옅은 빨간 배경 + 입력창 아래 빨간 문구. 목록 임시 줄은 "실패했다"만 짧게 보이므로, 무엇이 실패했는지는 다른 요청 실패와 같이 아래 문구로 (처음엔 목록에 보인다고 문구를 뺐으나 되돌림)
  - 힌트·초성 힌트·포기 실패: 빨간 테두리 + 옅은 빨간 배경 + 입력창 아래 빨간 문구 (목록에 띄울 단어가 없고, 입력창 안 버튼을 누른 직후라 시선이 입력창 근처). 모든 요청 실패가 같은 모양. 기능 하나가 고장 나면 다른 기능도 안 될 가능성이 커서 "막혀 있다" 표시는 모든 요청 실패에 같게
  - 입력창 표시가 풀리는 때는 11장과 같다 (글자를 칠 때, 다음 제출·힌트·초성 힌트·포기)
