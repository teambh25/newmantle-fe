# 결과창 (classic)

게임이 끝났을 때(정답 맞힘·포기) 뜨는 결과 모달과 메인 완료 표시. 입력창 위에 있던 결과 상자를 모달로 바꿨다(2026-11-13). 내력은 `decision.md`.
범위는 classic 테마. excel은 그대로.

코드 주석의 "요구사항 N"은 아래 번호를 가리킨다.

## 요구사항

1. 결과창 표시
   - 정답을 맞힌 순간, 또는 포기 확인 후 정답을 받은 순간에 결과 모달을 자동으로 연다. 포기도 같은 모달을 쓴다
   - 자동 표시는 그 순간의 행동이 기준이다. "자동으로 보여줬는지"를 따로 저장하지 않는다
     - 페이지를 불러올 때는 게임이 끝난 상태여도 자동으로 열지 않는다 (새로고침하면 다시 뜨지 않으므로 자연히 한 번만 뜬다)
     - 정답을 맞힌 뒤 단어를 더 제출해도 다시 열지 않는다
   - 바로 열지 않고 짧게 늦춰서 연다. 꽃가루와 날짜 제목의 초성이 정답으로 바뀌는 모습이 먼저 보이게 한다 (포기는 꽃가루 없이 제목이 바뀐 뒤). 늦추는 시간은 0.7초 (화면 확인 2026-11-13)
   - 정답·포기 순간부터 자동으로 열린 결과창을 닫을 때까지 입력창을 잠근다. 늦추는 동안 단어를 더 제출하지 않게 한다. 닫으면(계속 플레이·X·바깥·피드백) 다시 연다
2. 결과창 구성 (위에서부터)
   1. 축하 메시지와 시도 횟수를 한 묶음으로
      - 정답: 축하 이모지 + 정답을 맞혔다는 제목, 그 아래 "몇 번의 시도 끝에 맞혔다"는 문장
      - 포기: 축하 이모지 없이 포기했다는 제목, 그 아래 정답을 찾지 못해 아쉽다는 문장, 시도 횟수는 괄호로 덧붙임
      - 다음 퀴즈가 열리는 시각은 맨 아래 계속 플레이 버튼 바로 위에 작은 회색 글씨로. 버튼 문구가 "그때까지"로 이어 받는다(매일 00시 KST, `docs/spec/rules.md` R-3). 하루 한 번 게임임을 알린다. 오늘 추가 제출은 되므로 "더 플레이할 수 없다"고 쓰지 않는다
      - 결과창 문구는 모두 해요체로 통일한다
   2. 카테고리(`tag`) 뱃지 + 정답 단어, 그 아래 설명(`description`, 정답 선정 이유). 카테고리 뱃지는 정답 앞에 둔다. 정답 단어는 날짜 제목에 이미 크게 보이므로 크게 강조하지 않고 자연스럽게 한 번 더 쓴다
   3. 공유하기 / 피드백 보내기 버튼
   4. 계속 플레이: 결과창 맨 아래 가운데 작은 회색 글자 버튼(옅은 밑줄, 화살표 없음), 누르면 닫힘. 바로 위 다음 퀴즈 안내를 "그때까지"로 이어 받는다. 배너·큰 버튼으로 두지 않는다. 하루 한 번 게임이라 "한 번 더 플레이"로 읽히는 문구는 쓰지 않고, 오늘 게임에서 순위권 단어를 더 찾아본다는 뜻으로 쓴다 (단어 표의 "순위 / 순위 밖"과 같은 말). 포기했을 때도 보여준다 (포기 후에도 제출할 수 있음)
   5. 로그인 안내는 결과창 안에 두지 않는다. 대신 헤더 로그인 버튼을 강조한다 (요구사항 8). 결과창 안에 로그인 링크도 없다
   - 닫기: 오른쪽 위 X도 둔다. X, 바깥 누르기, 계속 플레이 모두 같은 닫기다
3. 피드백 보내기
   - 결과 모달을 닫고 피드백 창을 연다 (모달을 겹치지 않는다). 피드백 창은 설정 메뉴 "피드백 남기기"와 같은 창
   - 피드백 창을 닫으면(보냈든 안 보냈든) 결과창으로 돌아간다 (`../feedback/decision.md` Dec-18)
4. 메인 페이지 변경
   - 입력창 위의 기존 결과 상자는 없앤다. 결과 정보는 모달에만 둔다
   - 날짜·정답 제목과 입력창 사이에 한 줄짜리 완료 표시를 둔다: 결과 요약(정답 시도 횟수 / 포기) + 결과 다시 보기 버튼
   - 결과 다시 보기를 누르면 결과 모달을 다시 연다
   - 공유·피드백·로그인 안내는 메인에서 빼고 모달에만 둔다
   - 대결 바(CompetitiveBar)는 지금 위치 그대로 둔다 (공유 개편 `docs/todo/share.md`에서 정함)
   - 결과 모달을 닫거나 다시 열어도 정답·입력 기록과 게임 데이터는 바뀌지 않는다
5. 반응형 UI
   - PC: 가운데 모달. 최대 높이를 두고 넘치면 모달 안에서 스크롤
   - 모바일: 화면 아래에 붙는 바텀시트. 높이는 내용만큼, 최대 화면 높이의 약 90%. 넘치면 시트 안에서 스크롤
   - 새 라이브러리 없이 기존 Radix Dialog 하나로 PC·모바일 모양을 나눈다
   - 끌어서 닫기는 넣지 않는다. 끌 수 있어 보이는 손잡이 막대도 두지 않는다
6. 상태
   - 게임 완료 여부는 기존 저장 상태(정답 맞힘 / 포기)를 쓴다. 새로고침 후에도 완료 표시와 결과 다시 보기가 유지된다
   - 정답 정보는 제출 기록의 정답 항목(`answer`)에 이미 저장되므로 새로고침 후에도 모달에 보여줄 수 있다
7. 디자인 가이드 (세부 UI는 화면을 보며 피드백)
   - 독립적인 결과 카드 느낌. 흰 배경 + 메인 색(파랑) 포인트. 포기는 축하 색 없이 회색 톤 (초록은 화면 확인 후 뺌, 2026-11-13)
   - 축하 문구가 심심하지 않게 이모지를 곁들인다 (포기는 넣지 않음)
   - 카테고리와 설명은 보조 정보로 배치한다
   - 공유·피드백 버튼은 결과 정보와 시각적으로 구분한다
   - 공유·피드백은 내용 폭의 작은 버튼 한 쌍(가운데), 계속 플레이는 맨 아래 가운데 작은 글자(다음 퀴즈 안내와 함께 가운데 정렬). 닫는 행동이 맨 아래
   - 메인 완료 표시는 배경 없는 한 줄: 결과 요약 문장 · 결과창 보기 + 오른쪽 화살표. 줄 전체가 버튼. 배너·파란 글자 링크로 두지 않는다
8. 헤더 로그인 강조 (비로그인만)
   - 결과창이 열려 있는 동안 헤더 로그인 버튼을 어두운 배경 위로 밝게 띄우고(강조 테두리), 그 아래 "로그인해서 오늘 플레이 기록을 저장하라"는 말풍선을 함께 띄운다
   - 결과창이 열릴 때마다(자동·다시 보기) 뜨고, 결과창이 닫히면 같이 사라진다. 닫기 버튼·저장 여부는 없다
   - 결과창이 열려 있어도 강조된 로그인 버튼은 누를 수 있다 (로그인 페이지로 이동)
   - 이 말풍선이 떠 있는 동안 기존 헤더 로그인 말풍선(`header/plan.md` 5)은 숨긴다

## 기존 결과 상자에서 그대로 가는 것

이전 "결과 상자 정리"(커밋 fa5e0b9)에서 정한 것 중 모달에서도 유지한다.

- 정답을 맞혔을 때 토스트는 띄우지 않는다. 축하는 결과창에서, 꽃가루는 그대로
- 정답 좋았다/별로였다 투표는 없다. 의견은 피드백으로 받는다
- 공유 버튼 이름은 "공유하기". 공유 동작(대결형 링크)은 그대로
- 맞힘·포기 구분은 결과창 색이 맡고, 날짜 제목의 정답 타일은 둘 다 같은 색 (`word-list/plan.md` 4)

## 이번 범위 아님

- Amplitude 이벤트(모달 열림, 계속 플레이 클릭 등): 이번에는 넣지 않는다
- 랭킹 정보(선착순 몇 번째, 시도 횟수 상위 몇 %, 순위 그래프): 백엔드 작업이 필요해 나중에 결과창에 추가 예정. `docs/todo/ranking.md`
- Top 1000 단어: 나중에 결과창에서 들어가도록 추가 예정. 공유를 덜 하는 쪽으로 유도한다. `docs/todo/top-1000.md`
