# 피드백 창 정리
> 좋아요/싫어요 투표를 없애고 바로 의견을 적게 하며, 피드백은 퀴즈 날짜(KST)당 한 번만 보낼 수 있게 한다

## 1. Context
- 배경
  - 지금 피드백 창은 "재밌다/재미없다" 투표부터 받는다. "재미없다"를 눌러야만 입력창이 열려서, 게임을 즐긴 사람이 남기는 개선 제안은 받을 수 없다. 설정 메뉴에서 "피드백 남기기"를 누른 사람도 투표를 한 번 더 거쳐야 한다
  - 결과창을 다시 열 수 있게 바뀌었다(`docs/tasks/ui/result-box.md`). 그런데 보낸 기록이 컴포넌트 상태에만 남아서, 창을 닫았다 열거나 새로고침하면 투표와 피드백을 몇 번이든 다시 보낼 수 있다
  - 의견이 게임 개선에 쓰인다는 걸 창 안에서 알려 의견을 더 많이 받는다
- 외부 제약
  - 전송 대상은 기존 Make.com 웹훅(`hook.eu2.make.com/...`)을 그대로 쓴다. URL과 메서드(POST JSON)는 바꾸지 않는다
  - 웹훅 본문에 개인을 알아볼 수 있는 값(게스트 ID, Supabase 사용자 ID, 닉네임)을 넣지 않는다 (`docs/todo/privacy-terms.md`)
  - 피드백 창이 열리는 곳은 지금 두 군데다: 설정 메뉴 "피드백 남기기"(classic·excel), 결과창 "피드백 보내기"(classic). 새로 늘리지 않는다
  - excel 테마는 엑셀 셀 모양을 그대로 두고 동작만 바꾼다 (Dec-5)
  - UI 문구는 해요체로 쓴다. 정확한 문구는 사용자가 코드에서 다듬으므로 이 문서에는 규칙만 적는다
- 기존 패턴
  - 실패 알림: 힌트·포기·링크 복사 실패에 쓰는 실패 토스트(`useToast`, `variant: "destructive"`). 테스트는 하네스 `h.failureToastShown()`으로 확인 (`src/test/README.md`)
  - 날짜: `getKSTDateString()` (`src/utils/date.ts`)
  - 날짜별 게임 상태: localStorage `newmantle_game_data` (`useGameState`)
  - 결과창의 피드백 진입: `FeedbackDialog` (`classic/NewMantleForm/GameResult.tsx`). 결과창을 닫고 피드백 창을 연다

## 2. Scope
- In
  - 좋아요/싫어요 투표를 없앤다. 창을 열면 바로 입력창과 보내기 버튼이 보인다 (Dec-1)
  - 퀴즈 날짜(KST)당 1회만 보낼 수 있다. 보낸 날짜를 localStorage에 저장하고 classic·excel이 함께 쓴다 (Dec-2, Dec-5)
  - 보내면 브라우저 alert 대신 창 안에 감사 안내를 띄운다(토스트 없음). 같은 날 다시 열어도 같은 안내가 보이고, 진입 버튼은 그대로 둔다 (Dec-3, Dec-18)
  - 피드백 창을 닫으면(보냈든 안 보냈든) 연 곳으로 돌아간다. 설정에서 열었으면 메인, 결과창에서 열었으면 결과창 (Dec-18). 결과창 작업 `result-box.md` 요구사항 3과 R-4-2를 이에 맞춰 고친다
  - 보내기에 실패하면 실패 토스트를 띄운다. 쓴 내용은 남기고, 실패는 1회로 세지 않는다 (Dec-4)
  - 입력창을 여러 줄(textarea)로 바꾸고 최대 500자로 제한하며 남은 글자 수를 보여준다 (Dec-6)
  - 웹훅 본문에 퀴즈 날짜, 테마, 진입점, 그날 게임 상태를 더한다 (Dec-7)
  - Amplitude: `Survey Vote`를 없애고 `Feedback Opened`를 추가한다. `Feedback Submitted`에서는 본문을 빼고 글자 수·진입점·테마만 보낸다 (Dec-8)
  - 창 문구 구성: 제목, 안내 한 줄(무엇이든 적어 달라 + 게임 개선에 도움이 된다), 쓸 거리 예시를 담은 placeholder (Dec-9, Dec-15). 입력창·placeholder 글씨는 PC에서 작게 (Dec-17)
- Out
  - 토스트 위치(모바일 상단)와 실패 색(빨강) 정리: 모든 실패 표시에 공통이라 `docs/todo/error-ui.md`에서 다룬다
  - 닉네임 설정 alert 대체: error-ui todo
  - 웹훅 URL이 클라이언트에 노출된 문제, 서버 쪽 횟수 제한: 백엔드나 프록시가 필요하다 (Backlog)
  - 로그인 계정 단위의 1회 제한: 기기·브라우저 단위로 충분하다 (Dec-2)
  - `docs/todo/privacy-terms.md` 수집 항목 표 갱신: 다른 작업의 문서라 고치지 않는다. 바뀐 점은 완료할 때 보고만 한다
  - 정답 좋았다/별로였다 같은 별도 만족도 투표: 만들지 않는다 (`result-box.md` 결정과 같음)

## 4. Verification
- 자동 테스트(Vitest): 웹훅 요청은 fetch 경계에서 가로채 본문 필드(새로 넣은 필드 포함, 식별자 없음)를 확인한다. localStorage 저장값, Amplitude 이벤트와 속성(본문 없음), 화면 요소(역할·이름 기준. 문구는 검사하지 않음)를 확인한다
  - 투표 버튼이 없고 바로 입력할 수 있는지
  - 보낸 뒤 같은 날 다시 열면 입력창이 없고 안내가 보이는지, 날짜가 바뀌면(KST 0시) 다시 입력할 수 있는지
  - 실패하면 실패 토스트가 뜨고, 입력이 남고, 다시 보낼 수 있는지
  - 500자를 넘게 입력할 수 없는지, 공백만 있으면 보낼 수 없는지
  - 테마를 바꿔도 같은 날 1회 제한이 유지되는지
- 화면 확인: Phase 4 (사용자 dev 서버)

## 6. Glossary
- **피드백 창** — 설정 메뉴 "피드백 남기기"나 결과창 "피드백 보내기"로 여는 dialog. 두 곳 모두 같은 창이다
- **진입점(entry)** — 피드백 창을 연 곳. 설정 메뉴(`settings`) / 결과창(`result`)
- **퀴즈 날짜** — KST `YYYY-MM-DD`. 1회 제한의 기준이 되며, 보내는 시점의 KST 날짜를 쓴다 (Dec-10)
- **게임 상태** — 그날 퀴즈의 진행 상태: 진행 중 / 맞힘 / 포기
