# 검증: 피드백 창 정리

## 원칙

- 기준: `plan.md` Scope와 `decision.md`. 구현을 보고 케이스를 만들거나 바꾸지 않는다
- 요소는 role과 접근 가능한 이름으로 찾는다. 문구(안내·감사·토스트)는 검증하지 않는다
- 테스트 이름 앞에 케이스 ID를 붙인다 (`npx vitest run -t "F-2-1"`)
- 레이아웃·문구·excel 셀 모양은 jsdom에서 확인할 수 없어 수동으로 본다

## 검증 레벨

| 레벨 | 도구 | 대상 |
| --- | --- | --- |
| **화면** | vitest + React Testing Library + user-event, 메인(`Home`) + `Toaster` | 투표 없음, 웹훅 요청, 1회 제한, 실패 토스트, Amplitude |
| **수동** | 사용자 dev 서버 (모바일 + PC) | 문구, 레이아웃, excel 셀 모양 |

## mock 정책

`src/test/README.md`와 같다. 피드백 웹훅(Make.com)은 외부 경계라서 가짜 웹훅(`src/test/fakeFeedbackWebhook.ts`)으로 가로챈다. 받은 요청 본문을 기록하고, 다음 요청을 실패(500)시키거나 네트워크 오류로 만들거나 붙잡아 둘 수 있다. 게임 서버 요청은 지금처럼 `gameServer`로 간다.

## 요소 찾기

- 피드백 창: 열린 dialog 중 "게임 결과"가 아닌 것 (excel 피드백 창은 제목이 없어 이름으로 찾지 않는다)
- 설정 메뉴 진입: "설정" 버튼 → "피드백 남기기" 버튼
- 결과창 진입: "게임 결과" dialog 안의 이름에 "피드백"이 들어간 버튼
- 입력창: 피드백 창 안의 textbox. 보내기: 피드백 창 안의 이름에 "보내기"가 들어간 버튼
- 보낸 상태: 피드백 창 안에 textbox와 보내기 버튼이 없고, 감사 안내가 role `status` 영역으로 있음 (스크린리더에 보낸 결과가 읽히도록. 입력창이 없다는 것만으로는 지금의 투표 전 상태와 구분되지 않는다)
- 실패 토스트: role `status` (피드백 창 밖에 뜬다). 보내기 성공에는 토스트가 없다 (Dec-18)

## 사전 상태

| 이름 | 상태 |
| --- | --- |
| 기본 | 첫 방문 모달 봄(`newmantle_rule_modal_seen`) + 이전에 입력해 본 적 있음(`PLAYED`). 오늘 기록 없음 |
| `SOLVED` | 기본 + 오늘 정답 맞힘 저장 (결과창 다시 보기 가능) |

| `SENT_TODAY` | 기본 + 보낸 날짜 저장값이 오늘 KST 날짜 |
| `SENT_BEFORE` | 기본 + 보낸 날짜 저장값이 어제 KST 날짜 |

보낸 날짜 저장 키: `newmantle_feedback_sent_date`, 값은 KST `YYYY-MM-DD` (Dec-14)
