# 단어 목록 (classic)

입력창 아래 단어 목록(표)과 입력창 위 날짜·정답 제목. 내력은 `decision.md`. 순위 글씨 색과 순위 트랙(결과창으로 미룸)은 `rank-track.md`.

> 방금 항목은 **진행 상황 카드**가 보여 준다 → `../progress-card/plan.md`. 이 문서는 아래 기록 표와 날짜·정답 제목

## 표시 수단마다 뜻 하나

| 표시 | 뜻 |
| --- | --- |
| 순위·유사도 글씨 색 | 정답과의 거리 (단계 색, 2). 표는 순위순 |
| # 칸 아이콘 | 출처. 힌트 단어는 전구 |
| 진행 상황 카드 | 가장 최근 항목 (아래 기록 표는 모든 단어 순위순) |
| 입력창 위 가운데 제목 | 초성, 끝나면 정답. 둘 다 기록 표에는 없음 |

색 원칙: 초록은 정답 전용, 빨강·주황은 쓰지 않음 (멀다는 느낌 → 포기 유도). 힌트·포기 버튼을 검정으로 정한 것과 같은 이유. classic 테마는 다크 모드가 없어서 라이트만.

## 1. 표 구조: 진행 상황 카드와 기록 표 (2026-11-16)

```
          11월 16일 월요일
         오늘의 정답 [ㅅ][ㄹ]
 ┌────────────────────────────────┐
 │        햇볕 37위 (35.60)        │   ← 진행 상황 카드 (방금 항목 + 게이지, ../progress-card/)
 └────────────────────────────────┘
   #    단어          순위    유사도      ← 머리줄
  16    봄비           3위    55.31      ← 기록 표 (순위순, 방금 단어 포함)
  💡    새싹          24위    38.90
  17    햇볕          37위    35.60
  12    바람          45위    34.80
```

- 위는 **진행 상황 카드**(방금 항목), 아래는 **기록 표**(이름 "기록"인 표)
- 기록 표 = 순위를 아는 **모든 단어**(직접 낸 단어 + 힌트 단어)를 순위순으로. 낸 즉시 들어감
  - 방금 단어는 카드와 표 두 곳에 보인다. 카드는 "방금 무엇을 했나", 표는 "지금까지 낸 단어 중 가까운/먼 것"
  - 이미 낸 단어를 다시 내도 표에서 빠지지 않고 원래 번호로 자기 자리에 그대로
  - 표에 안 들어가는 것: 초성·정답(제목에 보임, 4), 없는 단어·제출 실패(저장 안 함), 제출 중 단어. 이것들은 카드에만
- 소제목 없음: 표가 하나뿐이라 설명할 필요가 없음. 카드와 표 사이 간격 12px
- 정렬: 순위 오름차순, 순위 밖은 유사도 내림차순 (`compareByRank`)
- 시작할 때(단어 없음)는 카드만 있고 표는 없음

## 2. 순위 단계

- 기록 표의 **순위·유사도 글씨 색**은 단계 색 (`rank-track.md` 3, 순위 밖 → 진한 회색, 100위 안부터 파랑). 단어 글씨는 검정
- 정렬만으로도 상대 순서는 보이지만, 높은 순위 단어가 색으로 빨리 눈에 들어오게 남김 (2026-11-16, 색 빼기를 검토했다가 유지). 진행 상황 카드 배너 순위 글씨도 같은 색
- 막대(유사도 바)는 원작과 겹쳐서 쓰지 않음
- 경계: 20 / 50 / 100 / 300. 첫 경계 20 = 힌트 한계 순위(`docs/rules/hint-giveup.md` A-6, `HINT_LIMIT_RANK`). 20위 이내는 힌트로 받을 수 없는 "아주 유사" 구간이라 가장 진하게
- `Similarity.tsx`는 excel 테마도 쓰므로 건드리지 않고 classic 표 안에서만 처리
- 경계값은 순위 → 단계 함수 하나(`src/utils/rankTier.ts`), 색은 글씨·트랙 공용(`tierColors.ts`)

## 3. 힌트 단어

- # 칸 전구 아이콘(`Lightbulb`, 검정, 이름 "힌트로 받은 단어")으로만 구분. 단어 글자는 입력 단어와 같은 검정 (2026-11-13, 갈색 글씨 없앰). 초성 줄 글자도 검정
- 이탤릭은 쓰지 않음 (한글 기울임은 억지로 비틀린 모양)
- 순위·유사도 글씨 색은 입력 단어와 같은 거리 색 (실제 순위가 있음)

## 4. 날짜·정답 제목

입력창 위 **가운데 두 줄 제목**. 정답이 `?` → 초성 → 정답 순으로 드러나는 한 문장.

```
            11월 13일 금요일            ← 작게, 회색
         오늘의 정답은?                 ← 크게, 굵게 (초성 사용 전)
         오늘의 정답 [ㅅ][ㄹ]           ← 초성 사용 후: 파란 타일
         오늘의 정답 [사][랑]           ← 게임 끝(맞힘·포기): 파란 타일
```

- 첫 줄 날짜: 요일을 풀어 씀 (`11월 13일 금요일`). 요일은 게임 날짜(KST `YYYY-MM-DD`)의 달력 요일이라 기기 타임존과 무관 (`formatGameDate`, classic만 씀)
- 둘째 줄: 초성 사용 전 질문, 사용 후 "정답 + 타일" 이름표. 글자마다 타일 (글자 수가 보임). 초성 사용 전에는 글자 수를 알려주면 안 되므로 타일 없이 `?`
- 타일 색: 초성·정답 모두 파랑 (`bg-blue-100` + `text-blue-700`). 제목 글자는 검정·회색 그대로. 맞힘·포기 구분은 결과창 색이 맡음 (`result-box/plan.md` 7)
- 스크린 리더는 정답을 한 단어로 읽게: 제목에 `sr-only` 한 단어, 타일은 `aria-hidden`
- 게임이 끝나면 초성 대신 정답 (저장된 기록의 `correct` 항목, 맞힘·포기 모두 저장됨)
- 크기: 날짜 `text-sm`(sm `text-base`), 둘째 줄 `text-xl`(sm `text-2xl`). 제목 위 여백 `mt-4`(sm `mt-6`)
- 높이 고정: 초성·정답 타일이 생겨도, 날짜를 불러오기 전에도 제목 높이 그대로
- 저장 데이터(`submittedWords`의 `rank: 0` 항목)는 그대로 두고 표시만 바꿈 → 기존 저장 데이터 호환
- 범위: classic. excel의 시트 이름은 그대로

## 5. 보이는 개수와 표 자리

- **기록 표 7줄** (`VISIBLE_HISTORY_COUNT`, 2026-11-16 방금 단어가 표에 들어가며 6 → 7). 7개를 넘으면 "더보기" / "접기"
- **표 자리를 미리 잡지 않음** (2026-11-16): 푸터는 처음엔 화면 맨 아래에 붙어 있다가(메인 `flex-grow`), 목록이 거기까지 자라면 한 줄씩 밀려 내려간다
  - 예전 최소 높이(7줄 + "더보기" 자리)는 카드가 들어오며 505px가 되어, 시작 화면부터 푸터가 화면 밖이었음
  - "더보기" 전까지 푸터를 늘 보이게 하는 안은 안 됨: 카드 + 7줄만 505px라 폰 화면(667~750px)에 헤더·입력창과 함께 안 들어감. 화면에 고정하면 목록을 가림
  - 측정(헤드리스): 375×667은 단어 4개째부터, 390×750·1024×768은 7개 무렵부터 푸터가 밀림
- 표와 푸터 사이 공백 40px (게임 영역 아래 여백 없음, 푸터 위 `mt-6`)
- jsdom은 높이를 계산하지 않아 자동 테스트 불가 → 헤드리스 크롬으로 단어 개수별 푸터 위치 측정 (V-16)
