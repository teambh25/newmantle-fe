# 검증: 모바일 UI 정리

## 원칙

- 기준: `plan.md`의 결정 사항. 구현을 보고 케이스를 만들거나 바꾸지 않는다
- 요소는 role과 접근 가능한 이름으로 찾는다. 문구는 검증하지 않는다
- 테스트 이름 앞에 케이스 ID를 붙인다
- 레이아웃·글씨 크기는 jsdom에서 확인할 수 없어 수동으로 본다

## I. 첫 입력 유도 말풍선 / 말풍선 순서

사전 상태

| 이름 | 상태 |
| --- | --- |
| `NEW` | localStorage 비어 있음 |
| `PLAYED` | 저장된 게임 기록에 단어가 있음 (이전 날짜) |

입력창 말풍선은 접근 가능한 이름 "입력 안내"인 버튼으로 찾는다.

| ID | 레벨 | 사전 상태 | 행동 | 기대 결과 |
| --- | --- | --- | --- | --- |
| I-1-1 | 화면 | `NEW`, 비로그인 | 메인 진입 → 모달 닫기 | 모달이 열려 있는 동안 입력창 말풍선 없음. 닫은 뒤 입력창 말풍선이 보이고 로그인 말풍선은 없음 |
| I-1-2 | 화면 | `NEW`, 비로그인, 모달 봄 | 첫 단어 입력 후 엔터 | 입력창 말풍선이 사라지고 로그인 말풍선이 보임 |
| I-1-3 | 화면 | I-1-2 이후 (첫 단어 제출함) | 다시 렌더링 | 입력창 말풍선 없음 |
| I-1-4 | 화면 | `NEW`, 비로그인, 모달 봄 | 입력창 말풍선 클릭 | 입력창에 포커스, 말풍선은 남아 있음 |
| I-1-6 | 화면 | `NEW`, 비로그인, 모달 봄 | 입력창 클릭 → 글자 입력 (제출 전) | 입력창 말풍선이 남아 있고 로그인 말풍선은 없음 |
| I-1-5 | 화면 | `NEW`, 비로그인, 모달 봄, StrictMode (개발 서버) | 메인 진입 후 아무것도 안 함 | 입력창 말풍선이 그대로 있음 (진입 직후 자동 포커스로 닫히지 않음) |
| I-4-1 | 화면 | `NEW` (모달 열림) | "시작하기"로 닫기 | 입력창에 포커스, 입력창 말풍선은 남아 있음 |
| I-4-2 | 화면 | `NEW` (모달 열림) | X / ESC / 바깥 클릭으로 닫기 | 입력창으로 포커스가 가지 않음 (모바일에서 키보드가 올라오지 않게), 입력창 말풍선은 남아 있음 |
| I-2-1 | 화면 | `PLAYED`, 비로그인, 모달 봄 | 메인 진입 | 입력창 말풍선 없음, 로그인 말풍선 보임 |
| I-2-2 | 화면 | 로그인 말풍선을 닫은 적 있음, 모달 봄 | 메인 진입 | 입력창 말풍선 없음 |
| I-3-1 | 화면 | `NEW` + 모달 봄, 입력 없이 로그인하고 돌아옴 | 메인 진입 → 첫 단어 제출 | 처음엔 입력창 말풍선만 (로그인·통계 말풍선 없음), 제출 후 통계 말풍선 |
| I-3-2 | 화면 | `PLAYED`, 로그인, 모달 봄 | 메인 진입 | 입력창 말풍선 없음, 통계 말풍선 보임 |
