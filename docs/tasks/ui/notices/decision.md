## 읽음 처리

- 기존 방식(공지 `date` vs 확인 시각)은 `date`가 날짜만이라 UTC 자정(KST 09:00)으로 비교되어, 같은 날 확인한 뒤 올라온 공지를 놓친다. 또 메인 방문만으로 읽음 처리돼서 배너가 한 번 뜨고 바로 사라진다 → 공지 `id`로 비교
- 10월 29~30일 장애 사과문(id 7, `date` 10-30, 기록용)을 추가하면서 "가장 큰 id = 최신" 가정이 깨짐 → 최신은 정렬 1순위

## 색 (2026-11-12)

문제

- 메인 띠는 옅은 파란 배경(`bg-blue-50`)인데, 종류 라벨("업데이트")도 파란 글씨(`text-blue-600`), 제목은 남색(`text-blue-900`) → 파랑 세 단계가 겹쳐 라벨이 어색함
- `/notices`의 종류 배지는 옅은 배경 + 진한 글씨 색 배지 (업데이트 초록 / 공지 파랑 / 이벤트 보라, `getTypeColor`). 공지 6개 중 5개가 업데이트라 초록만 반복
- 같은 "업데이트"가 띠(파랑)와 `/notices`(초록)에서 색이 다름
- 띠 배경은 파란색이 자연스러워서 유지하고 싶음

- 결정: E를 바탕으로, 장애 종류만 색을 쓴다. 통계의 정답·실패 색, 포기 확인 창의 빨강을 뺀 것(`giveup-dialog/plan.md` 1)과 같은 기준
- 메모
  - 띠 라벨 흰 글씨는 제외: 옅은 파란 배경 위 흰 글씨는 대비가 낮음
  - E로 가면 `getTypeColor`는 쓸 곳이 없어지지만 장애 배지 색 때문에 남김
  - 라벨과 제목 사이에 얇은 구분선이나 간격을 두면 굵기만으로 구분됨
- 비교해 보고 뺀 것
  - 띠 라벨 파랑(`text-blue-700`): 파란 배경 위 파랑이라 겹쳐 보임
  - 띠 제목 남색(`text-blue-900`): 파랗게 보여 회색으로. 장애 띠는 강조가 목적이라 빨강 유지
  - 장애 띠 제목 회색: 빨간 제목이 더 잘 보여서 되돌림
  - 진한 파랑 띠 + 흰 글씨: 강조는 세지만 매일 하는 게임 위에서 띠가 너무 먼저 보임
  - 업데이트 배지 초록: 통계의 정답 색과 뜻이 겹치고, 공지 대부분이 업데이트라 초록만 반복
- 같은 색 정리 중에 헤더 로그인 버튼 색도 봤다 → 유지 (`header/decision.md`)
