# 입력 단어 목록 UI (계획)

입력창 아래 단어 목록(표)이 한눈에 안 읽힌다. 순위 구분, 방금 입력한 단어, 힌트 단어, 초성 힌트, 보이는 개수를 한 번에 정리한다. 범위는 classic 테마.

- 코드
  - `src/components/classic/NewMantleForm/WordTable.tsx`: 표, 순위 칸 색
  - `src/components/classic/NewMantleForm/Similarity.tsx`: 유사도 칸 색 (`WordTable`과 같은 색 규칙이 복사돼 있음)
  - `src/components/classic/NewMantleForm/index.tsx`: "더보기" 버튼
  - `src/hooks/useGameState.ts` `sortedWords`: 정렬

## 1. 지금 동작

- 정렬: 가장 최근 항목(입력·힌트·초성 중 마지막 것) 하나를 맨 위에 고정하고, 나머지는 순위 오름차순, 순위 밖은 유사도 내림차순
- 항목 종류 (`SubmittedWord`)

| 종류 | 구분 방법 | 지금 표시 |
| --- | --- | --- |
| 내가 입력한 단어 | `attempt` ≥ 1 | # 칸에 번호 |
| 힌트 단어 | `attempt === -1` | # 칸에 전구 아이콘 (검정), 나머지는 입력 단어와 같음 |
| 초성 힌트 | `attempt === -1`, `rank === 0` | # 전구, 순위 "초성", 유사도 칸 "힌트" (파랑 굵게) |
| 정답 | `correct` | 줄 배경 연두 (`bg-green-50`), 순위 "정답!" |

- 줄 배경: 맨 위(방금 입력) `bg-muted` + `font-medium`, 정답 `bg-green-50`
- 순위 칸 글자색 3단계: 1–10 `blue-600` 굵게, 11–100 `blue-500` 약간 굵게, 101 이상 `gray-600`, 순위 밖 `gray-400`
- 기본 5줄, 6개 이상이면 "더보기" / "접기"

## 2. 문제

- [ ] **순위 구분이 안 됨**: 1–10과 11–100이 둘 다 파란 글씨라 진하기 차이가 거의 안 보임. 단계도 3개뿐
- [ ] **방금 입력한 단어가 강조가 안 됨**: 연회색 배경뿐이고 아래 목록과 경계가 없어 정렬된 1등처럼 보임
- [ ] **힌트 단어가 강조가 안 됨**: # 칸 전구(검정)만 다르고 나머지는 입력 단어와 같음
- [ ] **초성 힌트가 순위처럼 보임**: `rank === 0`이라 정렬하면 항상 위에서 두 번째. 파란 굵은 글씨라 상위 순위와 헷갈림. 단어가 쌓이면 계속 봐야 할 정보인데 눈에 덜 띔
- [ ] **5줄은 적음**: 10줄로 늘렸다가 7줄로 (3-5)
- [ ] **단어를 넣을 때마다 아래(푸터)가 밀림**: 표 자리를 미리 확보 (3-5)

## 3. 설계: 표시 수단마다 뜻 하나

| 표시 | 뜻 |
| --- | --- |
| 줄 배경 | 정답과의 거리 (파랑 단계) |
| 글자 스타일 | 출처. 힌트 단어는 갈색 글자, # 칸에 "힌트" |
| 굵은 구분선 | 방금 입력한 단어 (맨 위 고정 줄 아래) |
| 입력창 위 가운데 제목 | 초성, 끝나면 정답. 둘 다 표에는 없음 |

```
          11월 11일 수요일
        오늘의 정답 [ㅅ][ㄹ]
 ┌──────────────────────────────────┐
 │ 17   햇볕          37위    35.60 │ ← 방금 입력 (거리 색 그대로)
 ├━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━┤ ← 굵은 구분선
 │▓16   봄비           3위    55.31▓│ ← 1–20: 가장 진한 배경
 │▒힌트 새싹          24위    38.90▒│ ← 힌트: 갈색 글자
 │░12   바람          45위    34.80░│ ← 21–50
 │  1   책상         612위    12.04 │ ← 301 이상: 배경 없음
 └──────────────────────────────────┘
```

색 원칙: 초록은 정답 전용, 빨강·주황은 쓰지 않음 (멀다는 느낌 → 포기 유도). 힌트·포기 버튼을 검정으로 정한 것과 같은 이유

### 3-1. 줄 배경 (순위)

- 줄 전체를 옅은 파랑으로. 가까울수록 진하게. 배지·테두리·파란 글씨·굵게는 쓰지 않음 (번잡함)
- 막대(유사도 바)는 원작과 겹쳐서 쓰지 않음

| 순위 | 줄 |
| --- | --- |
| 1–20 | 가장 진한 파랑 배경 |
| 21–50 | 중간 파랑 배경 |
| 51–100 | 옅은 파랑 배경 |
| 101–300 | 아주 옅은 회청색 배경 |
| 301–999 | 배경 없음, 순위 글자 회색 |
| 순위 밖 | 배경 없음, 순위 글자 연회색 |

- 첫 경계 20 = 힌트 한계 순위(`docs/spec/hint-giveup.md` A-6, `HINT_LIMIT_RANK`). 20위 이내는 힌트로 받을 수 없는 "아주 유사" 구간이라 가장 진하게
- 유사도 칸은 회색 한 가지. `Similarity.tsx`는 excel 테마도 쓰므로 건드리지 않고 classic 표 안에서만 처리
- classic 테마는 다크 모드가 없어서 라이트만
- 경계값은 순위 → 단계 함수 하나(`src/utils/rankTier.ts`)로 빼서 로직 테스트

### 3-2. 방금 입력한 단어

- 맨 위 고정 + 아래 굵은 구분선. 배경은 거리 색 그대로 (회색 배경을 두면 "배경 = 거리"가 깨짐)
- 정답은 표에 없음 (3-4, 제목에 보임). 정답을 맞힌 직후에도 맨 위 고정 줄이 없음 → 구분선 없이 정렬 목록만
- 초성을 방금 받은 경우: 초성은 표에서 빠지므로 맨 위 고정 줄이 없음 → 구분선 없이 정렬 목록만

### 3-3. 힌트 단어

- 단어 글자를 갈색 계열(amber-700)로, # 칸에는 전구 대신 작은 "힌트" 글자
- 이탤릭은 쓰지 않음 (한글 기울임은 억지로 비틀린 모양)
- 줄 배경은 입력 단어와 같은 거리 색 (실제 순위가 있음)

### 3-4. 날짜·초성 제목 (2026-11-13 변경)

입력창 위 왼쪽의 작은 날짜 줄을 **가운데 두 줄 제목**으로 바꾸고, 초성 힌트를 제목 안에 넣는다. 정답이 `?` → 초성 → 정답 순으로 드러나는 한 문장.

```
            11월 13일 금요일            ← 작게, 회색
         오늘의 정답은?                 ← 크게, 굵게 (초성 사용 전)
         오늘의 정답 [ㅅ][ㄹ]           ← 초성 사용 후: 파란 타일
         오늘의 정답 [사][랑]           ← 게임 끝(맞힘·포기): 파란 타일
```

- 첫 줄 날짜: 요일을 풀어 씀 (`11월 13일 금요일`). 괄호 `(금)`는 다른 말 옆에 붙을 때 쓰는 줄임이라 혼자 있는 줄에서는 딱딱함. `formatGameDate` 형식을 바꿈 (classic만 씀)
- 둘째 줄 "오늘의": 붙임. 크게 쓴 둘째 줄만 읽어도 뜻이 통하게. UI에 어제 문제를 여는 기능이 없어 "오늘의"가 틀릴 일 없음
- 초성 사용 후 "정답은?" → "정답 ㅅㄹ": "은"을 빼서 질문 → 답이 걸린 이름표로
- 글자마다 타일: "초성"이라는 말 없이도 초성으로 읽히고 글자 수가 보임. 초성 사용 전에는 글자 수를 알려주면 안 되므로 타일 없이 `?`
- 타일 색: 초성·정답 모두 파랑 (`bg-blue-100` + `text-blue-700`) (2026-11-13 3차). 제목 글자는 검정·회색 그대로, 타일만 색
  - 처음엔 초성 노랑(힌트 단어 글자색) / 정답 맞힘 초록 / 포기 회색으로 나눴음
  - 결과 상자가 맞힘 초록·포기 회색(결과 상자 정리, 지금은 결과창 모달 `result-box.md` 요구사항 7)이 되면서 상자 바로 아래 같은 색 타일이 겹쳐 보여 어색함 → 맞힘·포기 구분은 결과 상자 색이 맡고, 타일은 "이게 정답"만 보여줌
  - 초성도 정답의 일부라 같은 색. 진행 중 `[ㅅ][ㄹ]`이 끝나면 같은 타일에서 `[사][랑]`으로 채워짐. 초성과 정답은 글자 모양으로 구분됨. 노랑의 근거(목록의 힌트 글자색)는 초성이 목록에서 빠지면서 약해짐. 회색은 비활성처럼 보이고 포기 상자 색과 겹쳐서 버림
  - 처음에 파랑을 뺀 이유(목록의 파랑 = 정답과의 거리, 버튼의 파랑 = 누르는 요소)는 연한 바탕 + 진한 글씨로 버튼과 구분해 감수
- 게임이 끝나면 초성 대신 정답 (이전 결정 "끝나면 숨김"을 대체). 정답은 저장된 기록의 `correct` 항목 (맞힘·포기 모두 저장됨)
- **정답은 표에서 뺌** (2026-11-13 2차): 제목에 정답이 보이므로 표의 정답 줄(연두, "정답!")은 중복. 초성과 같은 방식. 몇 번 만에 맞혔는지는 결과 상자에 있음. 포기한 정답 항목의 번호가 마지막 입력 번호와 겹쳐 보이던 것도 함께 사라짐
- 크기 (2026-11-13 2차, 처음보다 한 단계씩 키움): 날짜 `text-sm`(sm `text-base`), 둘째 줄 `text-xl`(sm `text-2xl`). 헤더와 붙어 보여서 제목 위 여백 `mt-4`(sm `mt-6`)
- 높이 고정: 초성·정답 타일이 생겨도 제목 높이가 그대로이도록 둘째 줄 높이를 고정하고 타일 높이를 그 안에 맞춤. 날짜를 불러오기 전에도 같은 높이
- 저장 데이터(`submittedWords`의 `rank: 0` 항목)는 그대로 두고 표시만 바꿈 → 기존 저장 데이터 호환
- 보이는 개수(7줄)에 초성은 세지 않음
- 제목이 한 줄 → 두 줄로 커진 만큼 표가 내려감. 푸터 위치 재측정 (V-16)
- 로그인 말풍선과 겹치는지 재확인 (V-17)

### 3-5. 보이는 개수

- 기본 5줄 → **7줄**. 맨 위 고정(방금 입력) 1줄 + 정렬 6줄. 8개 이상이면 "더보기"
- 10줄도 시도: 측정(헤드리스 크롬, 모바일 폭) 표 시작 214px, 줄 37px, 10번째 줄 끝 585px. 한 화면은 채우지만, 메인에 글 등 다른 내용을 넣을 계획이 있어 7줄로 줄임
- **표 자리 확보**: 단어가 적어도 표 영역이 7줄 + "더보기" 높이를 차지하도록 최소 높이를 둔다 (빈 줄이 아니라 공백). 플레이 중에 아래 내용(푸터 등)이 움직이지 않게
  - 빈 줄을 미리 그리는 안은 버림: 정렬된 표라 빈 줄이 "남은 순위"처럼 읽힘
  - "더보기"로 펼치면 그만큼 길어지는 건 그대로 (사용자가 직접 누른 것)
  - 제출 중 줄(0.3초 넘게 걸릴 때 보이는 회색 줄)이 있으면 단어 줄을 하나 덜 보여줘 전체 줄 수 유지
  - 초성이 붙어도 날짜 줄 높이가 그대로이도록 줄 높이 고정
- 표와 푸터 사이 공백: 128px → 40px (게임 영역 아래 `pb-16` 제거, 푸터 `mt-12` → `mt-6`). 표 자리를 확보한 만큼 다른 공백을 줄여 첫 화면에 푸터가 보이게
  - jsdom은 높이를 계산하지 않아 자동 테스트 불가 → 헤드리스 크롬으로 단어 개수별 푸터 위치 측정 (V-16)

## 6. 가까워짐을 더 강조할 후보 (미결정)

줄 배경은 "지금 이 단어가 얼마나 가까운지"(정적)만 보여준다. "점점 가까워진다"(시간 흐름)는 따로 보여줘야 한다. 막대(원작과 겹침)는 제외.

- A. **최고 순위 경신 표시**: 방금 입력한 단어가 이전 최고 순위보다 높으면 그 줄에 "최고!" 표시 + 배경이 한 번 반짝임. 경신 순간을 짚어줌 (추천)
- B. **최고 순위 발자취**: 표 위에 최고 순위가 바뀐 기록을 한 줄로 `612 → 288 → 45 → 3위`. 얼마나 다가왔는지 한눈에. 자리를 차지하고, 입력 수가 많으면 줄임 필요
- C. **온도 이모지**: 순위 칸 옆 🥶 → 🙂 → 🔥. 재미는 있지만 줄 배경과 같은 정보를 한 번 더 보여줘 번잡해질 수 있음

## 확인 방법

- 크롬 개발자 도구 기기 툴바(iPhone SE 등) + 실제 폰, 라이트·다크 모드
- 단어 20개 이상 + 힌트 2개 + 초성 힌트 + 정답 상태를 만들어 한 화면에서 비교
