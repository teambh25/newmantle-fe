# 개발용 화면 확인 페이지 (`/dev`)

개발 서버에서 화면 상태를 바로 만들어 보는 페이지. 내력은 `decision.md`.

1. 한 페이지(`/dev`)에서 가짜 단어 목록 설정과 실패 화면 설정을 함께 한다
2. 가짜 단어 목록: 순위권 단어를 매번 입력하지 않고 화면을 보기 위한 시나리오
   - 시나리오 버튼을 누르면 `localStorage`의 오늘 게임 기록(`newmantle_game_data`)을 가짜 목록으로 덮어쓰고 메인(`/`)으로 이동
   - 첫 방문 모달 확인 여부도 저장해서 모달 없이 바로 표가 보이게 함
   - "기록 지우기"로 원래(빈) 상태로
   - `?s=<시나리오>`로 열면 바로 적용 후 이동 (헤드리스 브라우저 캡처용)
   - 주의: 개발 서버(localhost)의 진행 기록을 덮어씀. 가짜 단어로 최고 순위가 정해지므로 힌트 버튼도 그 기준으로 동작
3. 예외 상황: 실패했을 때 화면을 보기 위한 버튼 4개. 누르면 그 요청이 **다음 한 번** 실패(500)하도록 해 두고 메인으로
   - 단어 제출 실패 / 힌트 실패 / 초성 힌트 실패 / 포기 실패
   - 실패 종류(500, 시간 초과 등)는 고르지 않음: 화면은 "없는 단어(404)"와 "그 밖의 실패" 두 갈래뿐이고, 갈래는 테스트(Y-2-1, Y-3-1)가 확인. 없는 단어는 직접 입력해 보면 됨
   - 한 번 실패하면 꺼짐
   - 힌트·초성 힌트·포기 실패는 기록을 비우고 시작 (가짜 목록에 20위 안 단어가 있으면 힌트 버튼이 꺼져 있어서)
4. 개발 서버의 모든 화면 왼쪽 아래에 DEV 표시를 두고 눌러서 `/dev`로 돌아간다. 실패가 대기 중이면 무엇인지도 보여주고 바로 취소할 수 있다
5. 개발 서버에서만 동작. 배포 빌드에는 페이지도, 응답을 바꾸는 코드도 들어가지 않는다
   - `next.config.mjs`가 개발 서버(phase `PHASE_DEVELOPMENT_SERVER`)일 때만 `*.dev.tsx`를 페이지로 인식. 빌드·배포에는 경로 자체가 없음 (`next build` 경로 목록에서 확인)
6. 메인 게임 코드는 건드리지 않는다. 진짜 서버 대신 브라우저에서 응답만 바꾼다
7. 저장소에 계속 둔다 (별도 브랜치는 저장 형식이 바뀌면 낡음)

## 코드

- `src/app/dev/page.dev.tsx`, `DevPanel.tsx`, `fixtures.ts`: 페이지, 시나리오 (1, 2)
- `src/app/dev/faults.ts`: 실패 주입 판별 (3)
- `src/app/dev/DevTools.tsx`, `DevBadge.tsx`, `src/app/layout.tsx`: DEV 표시, 개발 전용 분기 (4, 5)
