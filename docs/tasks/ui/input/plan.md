# 입력창 (classic)

입력창과 그 주변: 입력창 안 버튼, 첫 입력 유도 말풍선과 말풍선 순서, 제출 결과 안내. 내력은 `decision.md`.

## 1. 입력창 안 버튼과 폭

- 제출은 엔터. 큰 "제출" 글씨 버튼은 없다
- 입력창 안 오른쪽: 힌트·포기 글씨 버튼(아이콘 + 글씨) → 얇은 구분선 → 엔터 아이콘 버튼(접근 가능한 이름 `제출`)
  - 제출 잠금 규칙(`docs/rules/hint-giveup.md` D-2)은 엔터 아이콘 버튼에 그대로
  - 힌트·포기는 글씨가 보이므로 툴팁 없음. 동작·비활성 규칙은 그대로
  - 크기: 모바일(sm 미만) 글씨 `text-xs`·아이콘 14px, PC `text-sm`·16px·엔터 32px
  - 색: 모두 검정(`text-gray-900`). 초록(정답 색)·빨강(포기를 눈에 띄게 함, `hint-giveup.md` B의 의도와 반대)은 쓰지 않음
- 모바일(sm 미만)은 엔터 아이콘과 구분선을 숨긴다. 키보드 "보내기" 키·placeholder·첫 방문 안내로 엔터 제출을 알 수 있다. PC는 그대로
- 엔터 안내
  - 모바일 키보드 엔터 키를 "보내기"로 (`enterKeyHint="send"`)
  - placeholder: 평소 엔터 안내 한 줄. 없는 단어 안내가 있으면 그것 (3)
- 폭
  - PC(sm 이상): 입력창 최대 **420px**, 가운데. 게임 영역(제목·단어 목록)은 그보다 조금 넓은 **480px**. 헤더·공지는 그대로
    - 420 = 왼쪽 여백 12 + 가장 긴 안내 문구 약 212 + 간격 약 16 + 버튼 영역 176
  - 모바일: 화면 폭 그대로
- 범위: classic

## 2. 첫 입력 유도 말풍선, 말풍선 순서

- 입력창 말풍선 (첫 입력 유도)
  - 대상: 단어를 한 번도 입력해 본 적 없는 사람 (classic)
  - 위치: 입력창 바로 아래. 요청 실패 안내(3)가 떠 있으면 같은 자리라 숨김
  - 사라짐: 첫 단어를 제출(엔터 / 엔터 아이콘)하면. 입력창을 누르거나 글자를 치는 것만으로는 닫지 않는다. 말풍선을 누르면 입력창으로 포커스만 간다. 한 번 닫히면 다시 안 뜬다 (`localStorage` `newmantle_input_tooltip_done`)
  - 빈 입력으로 엔터는 제출이 아니므로 닫지 않는다. 서버가 오류를 돌려줘도 제출은 한 것이므로 닫는다
  - "한 번도 입력 안 함" 판단: 위 키가 없고, 기존 유저 흔적도 없을 때. 흔적 = 저장된 게임 기록(`newmantle_game_data`)에 단어가 있음, 또는 로그인 말풍선을 닫은 적 있음(`login-tooltip-dismissed`). 흔적이 있으면 바로 키를 저장한다
  - 기기 단위. 다른 기기에서 처음 들어온 로그인 유저도 한 번은 본다
- 순서 (한 번에 하나)
  1. 첫 방문 안내 모달
  2. 입력창 말풍선 (해당될 때, 첫 단어 제출까지)
  3. 헤더 말풍선: 비로그인 → 로그인 말풍선, 로그인 → 통계 말풍선 (각각 최초 1회, `header/plan.md` 4·5)
- 헤더 말풍선은 모달이 닫히고 입력창 말풍선이 끝난 뒤에만 보인다. 기존 유저는 입력창 말풍선이 없으므로 모달을 닫으면 바로 헤더 말풍선 (규칙 작업 M-6과 같음)
- 로그인부터 하는 경우: 모달을 닫고 입력 없이 바로 로그인 → 돌아오면 입력창 말풍선이 그대로, 로그인 말풍선은 안 뜸 → 첫 단어를 제출하면 통계 말풍선
- 비로그인으로 입력한 뒤 로그인하면 입력창 말풍선은 이미 끝났으므로 바로 통계 말풍선
- excel 테마는 그대로 (입력창 말풍선 없음, 로그인 말풍선은 기존대로)
- 첫 방문 모달을 닫은 뒤 포커스
  - "시작하기": 입력창에 커서. iOS Safari는 탭한 순간에 포커스해야 키보드를 올려주므로, 버튼을 누른 그 처리 안에서 모달을 닫고 바로 포커스
  - X / ESC / 바깥 클릭: 입력창으로 보내지 않는다 ("일단 닫기". 모바일에서 원치 않는 키보드가 화면을 가리지 않게). X는 그대로 둔다 (규칙 작업 M-4 유지)

## 3. 제출 결과 안내

> 2026-11-15: 안내 자리가 진행 상황 카드 배너로 바뀜 → `../progress-card/plan.md` 3. 없는 단어 placeholder 안내·입력창 오류 상태·입력창 아래 요청 실패 문구는 없앰. 아래 표의 "입력창" 칸 중 이 셋은 지난 내용. 제출 실패 때 단어를 남기는 것과 빨간 테두리는 그대로

전제: 사용자는 단어를 내고 입력창이 아니라 **단어 목록 맨 위(방금 입력 칸)**를 보며 다음 단어를 친다. 그래서 제출 결과 안내는 방금 입력 칸이 주로 맡고, 입력창 쪽은 보조. 방금 입력 칸의 구조는 `word-list/plan.md` 1.

| 상황 | 방금 입력 칸 | 입력창 | 입력창 아래 |
| --- | --- | --- | --- |
| 없는 단어 (404) | 임시 줄 (단어 + 없는 단어 표시), 직전 단어는 기록 표로 | 비움. placeholder에 단어를 넣은 안내(평소 placeholder 색). `aria-invalid`. 스크린리더용 안 보이는 알림 | 없음 |
| 단어 제출 실패 (서버·네트워크·3초 시간 초과·날짜) | 임시 줄 (단어 + 실패 표시), 직전 단어는 기록 표로 | 단어 남김(엔터만 다시 누르면 재시도), 빨간 테두리 + 옅은 빨간 배경. `aria-invalid` 아님 | 빨간 원 아이콘 + 빨간 문구 |
| 힌트 / 초성 힌트 / 포기 실패 | 그대로 | 빨간 테두리 + 옅은 빨간 배경 | 빨간 원 아이콘 + 빨간 문구 |
| 이미 제출한 단어 | 그 단어가 올라옴, 번호 칸에 반복 아이콘. 요청 없음 | 비움 | 없음 |
| 링크 복사 성공·실패 | — | — | 토스트 (입력과 상관없는 알림이라 그대로) |

### 3-1. 임시 줄 (없는 단어·제출 실패)

- 방금 입력 칸 자리에 뜬다. 새 줄을 하나 더 얹지 않는다
- 모양은 보통 줄과 같다 (배경 그대로, 4칸)
  - 번호 칸: 시도 횟수에 안 들어가므로 표시. 없는 단어 "-" 글자, 제출 실패 원 경고 아이콘(`CircleAlert`), 보통 글씨 색
  - 단어 칸: 친 단어 그대로 (긴 단어는 끝 "…")
  - 순위·유사도 칸: 숫자 대신 상태. 없는 단어는 둘 다 "없다"는 표시, 제출 실패는 둘 다 오류 표시
- 저장하지 않는다 (localStorage·통계에 안 남음, 새로고침하면 사라짐). 다음 항목이 와도 기록 표에 안 들어간다
- 같은 없는 단어를 다시 내도 막지 않고 임시 줄을 다시 띄운다
- 바뀌는 때: 방금 입력 칸에 다른 항목이 올 때 (다음 제출, 이미 낸 단어 다시 내기, 힌트·초성·포기). 다음 단어도 없는 단어거나 실패면 내용만 바뀜
  - 제출을 시작할 때가 아니라 **응답이 올 때** 바꾼다. 응답이 0.3초 넘게 걸리면 그 사이는 제출 중 줄
- 입력창에 글자를 쳐도 남는다 (다음 단어를 고르는 동안 볼 수 있게)
- 보이는 줄 수는 그대로 7줄: 임시 줄이 방금 입력 칸을 차지하므로 단어가 7개뿐이어도 "더보기"가 나온다

### 3-2. 이미 제출한 단어

- 서버에 요청하지 않고 그 단어를 방금 입력 칸으로 올리고, 번호 칸에 반복 아이콘(`Repeat`, 보통 글씨 색)을 번호 대신 둔다. 순위·유사도는 그대로
- 방금 입력 칸에 다음 항목(입력·힌트·초성·정답)이 오면 기록 표 자기 자리에서 원래 번호로. 저장하지 않는다
- 스크린리더는 아이콘 이름("이미 입력한 단어")으로 읽음

### 3-3. 입력창 쪽

- 없는 단어: 입력창을 비우고 placeholder에 안내. 문구 규칙은 4. 입력창 테두리·배경은 바꾸지 않음. placeholder는 스크린리더가 바로 읽지 않으므로 같은 안내를 안 보이는 알림(`role="alert"`, `sr-only`)으로도
- 요청 실패(단어 제출·힌트·초성 힌트·포기 모두 같은 모양): 빨간 테두리 + 옅은 빨간 배경(`bg-red-50`) + 입력창 아래 빨간 원 아이콘(`CircleAlert`)과 빨간 작은 글씨(모바일 11px, PC 12px)
  - 아래 문구는 입력창과 단어 목록 사이 여백에 겹쳐 띄워 목록이 밀리지 않게
  - 문구는 원인(서버·네트워크 등)은 적지 않고 어떤 기능이 실패했는지만. 사용자가 잘못한 것처럼 읽히지 않게
- 안내는 한 번에 하나: 없는 단어 안내 중 요청이 실패하면 없는 단어 표시를 풀고 요청 실패만
- 입력창 표시가 풀리는 때: 입력창 글자를 고칠 때, 다음 제출·힌트·초성 힌트·포기를 누를 때
- `useGameState`는 실패 처리 함수(`onRequestError(종류)`)를 받으면 토스트 대신 그 함수를 부른다. 안 받으면 토스트 (excel 테마는 그대로: 입력을 지우고 placeholder에 안내, 요청 실패는 토스트)

## 4. 안내 문구 (없는 단어)

- 문구 규칙만 여기 적고 정확한 글자는 코드에서 정한다
- 입력한 단어를 넣는다. 조사 은/는은 단어 마지막 글자 받침으로 고른다 (한글이 아니면 둘 다 적는 형태)
- 단어가 6글자를 넘으면 앞 5글자 + "…"로 줄인다. 조사는 원래 단어 마지막 글자로 고른다
- 짧게: 360px 폰 글자 칸(약 212px)에 가장 긴 문구가 들어가야 한다. 입력창 끝 CSS 말줄임은 쓰지 않는다 (단어 말줄임과 두 번 겹침)
