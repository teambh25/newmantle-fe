# 입력창: 결정 기록

## 입력창 버튼 (2026-11-11 ~ 13)

- 모바일은 마우스를 올리는 동작이 없어 툴팁이 안 뜨고, 아이콘만으로는 무슨 버튼인지 모름 → 힌트·포기를 아이콘 + 글씨 버튼으로. 글씨만 두면 두 버튼 경계가 안 보여 아이콘으로 구분
- PC·모바일 모두 엔터로 연속 입력하는 게 편해서 큰 "제출" 버튼을 없앰
- 버튼 위치 경과: 입력창 아래 오른쪽 → 단어 목록 오른쪽 위 → 입력창 안(현재)
- 처음 전용 placeholder("아무 단어나 ...")는 버튼 영역이 넓어져 안 들어가서 없앰. 첫 입력 유도는 첫 방문 모달과 입력창 말풍선이 맡음
- 모바일 엔터 아이콘·구분선 숨김 (11-13): 버튼 영역이 입력창의 40% 넘게 차지해 글자 칸이 왼쪽에 몰려 보이고, 포기가 엔터 옆에 붙어 있었음
- PC 폭 (11-13): 672px 전체를 쓰면 글자 칸 대부분이 비어 입력이 왼쪽에 쏠려 보임 → 입력창 420px
  - 입력창만 줄이니 아래 단어 목록이 넓어 어색하고 단어 칸 공백이 큼 → 한때 게임 영역 전체를 420px로 맞춤
  - 목록이 입력창과 똑같아 답답해 보여 게임 영역 480px, 입력창 420px으로 (목록이 입력창보다 약간 넓은 편이 자연스러움)
  - 모바일은 이미 거의 전체 폭이라 줄이면 아래 표와 들쭉날쭉해서 그대로

## 첫 입력 유도 말풍선 (2026-11-11)

- placeholder를 짧게 줄이면서 빠진 첫 입력 유도를 말풍선으로 맡김. 말풍선이 여러 개 동시에 뜨지 않게 순서를 정함
- 닫는 때 경과
  - 처음: 입력창 포커스로 닫음 → 개발 서버 StrictMode에서 진입 직후 자동 포커스가 생겨(`useGameForm`의 첫 마운트 건너뛰기가 두 번째 effect 실행에서 풀림) 사용자가 보기도 전에 닫힘 (V-11)
  - 누르기·키 입력으로 닫기 → 제출까지 안내가 보이도록 **첫 제출**로 닫기 (현재)
- 모달을 닫은 뒤 포커스: 이전에는 닫는 방법에 따라 입력창으로 가기도 하고 안 가기도 했음 (의도한 동작 없음, Radix가 열리기 전 포커스로 되돌리는 동작에 따라 달라짐)
  - 한때 모든 닫기 방법에서 입력창으로 보냄 → "시작하기"만 입력창으로(B안). X / ESC / 바깥 클릭은 "일단 닫기"라는 뜻이고, 모바일에서 원치 않는 키보드가 올라와 화면을 가림

## 없는 단어·요청 실패 안내 (2026-11-13)

같은 날 여러 번 바뀌었다. 차수 순서대로.

- 시작: 입력창 placeholder에 "없는 단어입니다"만 떠서 눈에 잘 안 띔
- 알림창은 쓰지 않음: 자주 나오는 가벼운 실수라 흐름이 끊기고, 모바일에서 키보드가 내려감
- 1차: 입력창 테두리를 빨갛게 (placeholder 문구는 빨간 글씨). 다음 제출 때 풀림
- 2차: 문구에 입력한 단어를 넣음. 조사 은/는은 마지막 글자 받침으로 고름. 글자색은 테두리와 같은 빨강
- 3차: 문구 속 단어가 6글자를 넘으면 앞 5글자 + "…". 가장 긴 문구가 약 212px로 고정돼 입력창 폭을 줄일 수 있었음
  - 360px 폰은 글자 칸이 약 204px라 그래도 끝이 잘림 → 입력창 끝 CSS 말줄임으로
  - 한때 모바일 안내 문구를 14px로 줄여 들어가게 했으나, 글자가 작아져 오히려 공백이 많아 보여 되돌림
- 4차: 작은 폰에서는 끝의 "…"도 잘려 안 보임 → 문구를 줄임 (가장 긴 문구 약 182px)
  - 테두리만 빨가면 안의 힌트·포기·엔터 버튼은 그대로라 어색 → 옅은 빨간 배경(`bg-red-50`) 추가. 꽉 찬 빨강은 과하고 글씨가 안 보임
- 5차: 안내를 입력창 **아래**로. 2~4차의 문구 길이·말줄임·배경 문제가 모두 사라짐
  - 없는 단어를 내면 입력한 단어를 남김 (오타면 고쳐서 바로 다시). 단어를 문구에 넣지 않으므로 조사·말줄임 함수는 없앰
  - 빨간 테두리 + 아래 경고 아이콘·작은 빨간 글씨(모바일 11px, PC 12px). 옅은 빨간 배경은 다시 넣어 비교한 뒤 뺌 (아래 경고가 이유를 알려 줌)
- 요청 실패도 입력창 아래로 (11장): PC에서 토스트가 오른쪽 아래에 떠서 입력창(화면 위 가운데)을 보는 사용자 눈에 안 띔. 모바일은 위에 떠서 괜찮았음. 힌트·포기 버튼도 입력창 안이라 단어 제출·힌트·초성 힌트·포기 실패를 모두 입력창 아래로
  - 처음엔 색으로 종류를 나눔: 없는 단어 노랑(2px 테두리 `ring-1` + 진회색 글씨, 아래 경고였을 땐 노란 세모 아이콘), 요청 실패 빨강(테두리 + 옅은 빨간 배경 + 빨간 글씨 + 원 아이콘). 1px 노란 테두리는 잘 안 보였고, 노란 글씨는 작은 글자에서 읽기 어려웠음
  - 실패 문구가 사용자 잘못처럼 읽힘 → 어떤 기능이 실패했는지만 (사용자가 코드에서 직접 수정)
  - 버린 것: "빨간 표시는 없는 단어에만, 그 밖의 실패는 토스트"
- 6차: 없는 단어를 내면 입력창을 **비우고** 안내를 다시 placeholder에
  - 없는 단어는 오타보다 게임 사전에 없는 경우가 많아 보임. 남기면 매번 지우고 다시 쳐야 하고, 오타라도 몇 글자라 다시 치는 수고가 작다 (없는 단어 이유를 따로 기록하는 데이터는 없음)
  - 비우면 무엇을 쳤는지 사라지므로 문구에 단어를 다시 넣음 → 조사·줄이기 함수(`utils/korean`) 되살림. 입력창 끝 CSS 말줄임은 넣지 않음 (말줄임 두 번). 엔터 아이콘을 빼며 모바일 글자 칸이 넓어져 계산상 360px에서도 들어감
  - 노랑이 디자인에 안 어울림. 회색 테두리는 평소 테두리와 구분이 안 되고, 회색 배경은 제출 중 잠긴 입력창처럼 보임 → 자리로 나눔: 내가 친 단어가 문제면 입력창 안, 기능이 고장 나면 입력창 아래
  - 없는 단어 표시 모양을 차례로 써 봄: 빨간 테두리 + 빨간 글씨 → 빨간 테두리 + 검정 글씨 → 빨간 글씨만 → 검정 글씨만 → (12장) 평소 placeholder 색
- 12장: 없는 단어·제출 실패는 **단어 목록 맨 위**에
  - 플레이 습관: 단어를 내고 입력창이 아니라 목록 맨 위(방금 낸 단어의 순위·유사도)를 보며 다음 단어를 친다 (사용자 확인). 제출 중 스피너 줄도 같은 자리
  - 처음엔 스피너 줄처럼 회색 줄을 맨 위에 하나 더 얹음 → 구분선 위가 직전 입력이 아니게 돼서, 새 줄 없이 그 자리를 임시 줄이 씀 (V-23)
  - 처음엔 순위·유사도 칸을 합쳐 안내 하나만 적음 → 글자가 다른 줄의 순위·유사도 위치와 안 맞아 줄 모양이 달라 보여 4칸으로 나눔
  - 번호 칸 표시: "-" → 금지 `Ban`(뜻이 너무 셈) → 빼기 `Minus` 아이콘(너무 큼) → "-" 글자로 되돌림
  - 같은 없는 단어를 다시 내도 막지 않음: 서버가 404로 답하고 시도 횟수에 안 들어가 손해가 없고, 저장해 봐야 정렬 때문에 목록 맨 아래라 거의 안 보임
  - 단어 7개 + 임시 줄이면 7번째 단어가 가려지고 "더보기"가 없던 결함 (리뷰에서 발견) → 임시 줄 자리를 셈
  - 단어 제출 실패: 처음엔 목록 임시 줄에 보인다고 입력창 아래 문구를 뺐으나, 임시 줄은 "실패했다"만 짧게 보여 무엇이 실패했는지 알 수 없어 되돌림
  - 힌트·초성 힌트·포기 실패도 빨간 테두리 + 옅은 빨간 배경: 목록에 띄울 단어가 없고, 입력창 안 버튼을 누른 직후라 시선이 입력창 근처. 기능 하나가 고장 나면 다른 기능도 안 될 가능성이 커서 "막혀 있다" 표시는 모든 요청 실패에 같게
  - 임시 줄을 바꾸는 때: 처음엔 제출을 시작할 때 지움 → 없는 단어를 연속으로 내면 응답 전에 직전 단어가 방금 입력 칸으로 잠깐 돌아왔다가 다시 내려가 깜빡여 보임 (V-13) → 응답이 올 때 바꿈

## 이미 제출한 단어 (2026-11-13)

- 처음: 안내 없이 목록 맨 위로만 올림
- 반복 아이콘을 번호 대신: "아까 냈던 거네"를 알아채게 해 몰입을 돕고, 시도 횟수가 늘었나 하는 걱정을 던다
- 아이콘 자리: 번호 칸은 힌트 줄이 이미 줄 종류를 알리는 자리라 같은 방식. 단어 옆 글자는 좁은 폰에서 긴 단어와 자리를 다퉈 뺌
- 아이콘 색: 처음엔 연회색 → 번호 자리라 흐리면 비활성처럼 보여 보통 글씨 색으로 (V-24)
- 포기·초성 뒤에도 반복 아이콘이 남는 경우가 있었음 (리뷰에서 발견) → 방금 입력 칸을 "가장 최근 항목"으로 정의하면서 해결 (`word-list/decision.md`)
