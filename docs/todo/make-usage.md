# Make.com 사용량 주의

피드백 웹훅(Make.com → Google 시트)은 Make 월 사용량을 쓴다. 한도에 가까워지면 경고 메일이 온다.

## 사용처

- `src/hooks/useFeedback.ts`의 `WEBHOOK_URL` (피드백 전송 한 곳뿐)
- 요청은 "보내기"를 누를 때만 나간다. 창을 여는 것만으로는 나가지 않는다.

## 사용량이 늘어나는 경우

- 테스트로 여러 번 보낼 때. 실제 시트에 행이 쌓이고 operations도 쓴다
- 유저가 피드백을 많이 보낼 때 (UI 개편 후 excel 결과창에도 입력칸이 생겼다)
- 웹훅 URL이 클라이언트 코드에 노출되어 있어 누구나 요청을 보낼 수 있다
- 시나리오가 실패해도 실행 횟수로 잡힐 수 있다

## 테스트할 때

- 개발 중 테스트는 가짜 웹훅(`src/test/fakeFeedbackWebhook.ts`)을 쓴다. 실제 Make로 보내지 않는다
- 실제 웹훅으로 확인해야 할 때는 한두 번만 보내고, 보낸 뒤 시트에서 행을 지운다
- 보내기 전후로 Make 실행 기록에서 operations 수를 확인한다

## 최근 관찰 (2026-11-17)

- UI 업데이트 배포와 피드백 전송 테스트가 겹친 시기에 사용량이 순간적으로 많아진 것으로 추정된다. 원인은 아직 확인하지 않았다
- 당분간 사용량 그래프와 실행 기록을 주기적으로 보고, 같은 패턴이 반복되는지 주의 깊게 관찰한다

- [ ] 월별 사용량 그래프에서 급증한 날짜와 실행 기록 대조
- [ ] 실행 기록의 요청 본문이 우리 앱 형식인지 (다른 곳에서 온 요청 여부)
- [ ] 시나리오 실패 실행이 있는지
