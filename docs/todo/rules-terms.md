# 규칙 페이지 / 이용약관 페이지 (계획)

게임 규칙을 `/rules`(가칭), 이용약관을 `/terms`로 분리한다. 지금은 규칙 설명이 메인 하단 "도움말" 2개뿐이고, 약관 페이지는 없다. 아직 구현 전이라 현재 상태와 들어갈 내용, 결정할 것만 기록.

---

## 1. 현재 상태

### 1-1. 규칙 관련

| 위치 | 내용 | 코드 |
| --- | --- | --- |
| 메인 "도움말" (아코디언) | FAQ 2개<br>① 어떻게 플레이하나요? → 단어 입력, 유사도 확인, 더 높은 단어 추측 (4줄)<br>② 다른 단어를 맞히고 싶어요 → 매일 00시에 정답이 바뀜 | `src/static/faq.ts`<br>classic: `src/components/HelpSection.tsx`<br>excel: `src/components/excel/HelpSection.tsx` (`startRow=20`, 행 번호 레이아웃) |
| 메인 최하단 | "이 게임은 원작인 꼬맨틀의 개선된 버전입니다" + 꼬맨틀 링크 | `src/components/{classic,excel}/GameDescription.tsx` |
| 힌트 / 포기 버튼, 확인 창 | 버튼 자체와 확인 창 문구로만 안내 | `docs/spec/hint-giveup.md` |

**설명되지 않는 것** (게임 안에서만 알 수 있음)

- 순위 / 유사도의 의미: 순위 1~999, "순위 밖", 1위 = 정답 제외 가장 가까운 단어
- 힌트: 몇 위 단어를 주는지(최고 순위 × 0.75), 20위 이내면 막힘
- 초성 힌트: 포기 버튼을 눌러야 받을 수 있고 하루 1회
- 포기: 정답 공개, 이후 입력은 기록에 반영 안 됨, 시도 횟수 = 입력 횟수
- 정답 후 입력: 계속 가능하지만 기록 안 됨
- 정답이 바뀌는 기준 시간대(KST)
- 기록 / 통계: 비로그인(게스트)도 기록되는지, 로그인하면 게스트 기록이 연결되는지(`useGuestLink`)
- 도전장(대결형 공유) 동작 (`docs/todo/share.md`)
- 테마(classic / excel) 전환

### 1-2. 약관 / 정책 관련

- 이용약관, 개인정보처리방침 페이지 **없음**
- classic 푸터(`src/components/classic/Footer.tsx`): "이용약관 / 개인정보처리방침 / 문의하기" 링크가 있지만 전부 `href="#"`
- excel 푸터(`src/components/excel/Footer.tsx`): "Terms / Privacy / Support" 링크(`#`)가 있지만 **메인에서 렌더링하지 않음** (`page.tsx`에서 import만 하고 사용 안 함). excel 테마에서는 약관 진입점이 아예 없음
- 로그인 화면(`src/app/login/page.tsx`)과 닉네임 설정(`NicknameSetupModal`)에 약관 동의 절차 없음
- 회원 탈퇴 기능 없음

### 1-3. 현재 수집·저장하는 정보 (약관 / 개인정보처리방침 작성 근거)

| 정보 | 어디로 | 비고 |
| --- | --- | --- |
| Google 계정 (이메일, 이름 등 OAuth 제공 정보) | Supabase Auth | 로그인 시. Google 로그인만 지원 |
| 닉네임 | Supabase `profiles` | 최초 로그인 시 필수 입력, 중복 불가. 공개 범위는 아직 없음(랭킹 도입 시 공개됨) |
| 게스트 ID (UUID) | localStorage `newmantle_guest_id`, 서버 요청 헤더 `X-Guest-Id` | 비로그인 플레이 기록 식별 |
| 게임 기록 (제출 단어, 시도/힌트/포기) | 서버 통계 + localStorage `newmantle_game_data` | 서버는 날짜별 통계, 공유 링크로 `GET /v2/stats/{type}/{id}/{date}`가 인증 없이 조회 가능 |
| 공유 링크의 `sharer_id` | URL | 로그인 유저면 Supabase user id가 링크에 그대로 들어감 |
| 이용 행태 | Amplitude | 이벤트 + 세션 추적(`defaultTracking: { sessions: true }`), 로그인 시 `setUserId(user.id)`. 피드백 본문도 `Feedback Submitted` 이벤트에 들어감 |
| 피드백 본문 | Make.com 웹훅 (설정 → 설문) | 국외(EU) 서버로 전송 |
| 기타 localStorage | 테마, 공지 확인 시각, 로그인 툴팁 닫음 여부, 게스트 연결 대기 | 쿠키 아님, 기기에만 저장 |

## 2. 규칙 페이지 (`/rules`)

### 2-1. 들어갈 내용

- [ ] **기본 규칙**: 매일 정답 단어 1개, 단어를 입력하면 정답과의 유사도·순위를 알려줌
- [ ] **유사도 / 순위 읽는 법**
  - 순위 1~999위, 1위는 정답 다음으로 가까운 단어
  - 1000위 밖은 "순위 밖"
  - 유사도 수치의 의미 (몇 점부터 가까운 건지, 예시 표가 있으면 좋음)
  - 원작(꼬맨틀)과 다른 점: 개선된 모델 (현재 `GameDescription` 문구)
- [ ] **정답 교체 시간**: 매일 00시(KST). 어제 문제 플레이 가능 여부를 안내할지 (API는 오늘·어제만 허용, UI에서 어제 문제를 노출하는지 확인 필요)
- [ ] **힌트**: 현재 최고 순위보다 높은 순위의 단어를 줌, 20위 이내에 도달하면 더 못 받음, 사용 횟수가 기록에 남음
- [ ] **초성 힌트**: 포기 버튼 → 하루 1회
- [ ] **포기**: 정답 공개, 이후 입력은 기록 안 됨, 시도 횟수 = 포기 시점의 입력 횟수
- [ ] **정답 이후**: 단어를 더 넣어볼 수 있지만 기록 안 됨
- [ ] **기록 / 통계**: 게스트도 기기 기준으로 기록, 로그인하면 계정에 연결, 기기·브라우저 데이터 삭제 시 게스트 기록 유실
- [ ] **도전장**: 링크로 친구와 시도 횟수 비교, 당일 문제에만 적용
- [ ] (랭킹 도입 시) 랭킹 기준, 힌트 가중치, 포기 기록 처리 (`docs/todo/results.md`)
- [ ] FAQ (기존 2개 + 자주 받는 문의)

### 2-2. 고민할 것

- **메인 도움말을 어떻게 할지**
  - (a) 메인 도움말 유지 + "자세한 규칙 보기" 링크
  - (b) 메인에서 도움말 제거, 헤더 아이콘(? 버튼)으로 `/rules` 진입
  - (c) 첫 방문 시 모달로 요약 노출 + `/rules`
  - 공지 분리(`docs/todo/notices.md`)와 같이 하면 메인 하단이 정리됨
- **수치를 어디서 가져올지**: 0.75, 20위, 999위 같은 값을 규칙 페이지에 하드코딩하면 스펙 변경 시 어긋남. 힌트 로직의 상수를 export해서 문구에 쓰는 것을 고려. 다만 공식 자체(× 0.75)를 공개할지, "더 가까운 단어를 알려줘요" 정도로 둘지도 결정 필요
- **기준 문서**: 내부 스펙은 `docs/spec/hint-giveup.md`. 규칙 페이지는 유저용 요약이므로 스펙 변경 시 같이 고칠 것을 체크리스트화
- **테마**: `/stats`처럼 classic만 / excel도 지원. excel 지원 시 하단 탭 바에 "규칙" 탭 추가가 자연스러움 (공지 페이지와 같은 결정)
- **FAQ 데이터**: `src/static/faq.ts`를 규칙 페이지와 메인이 같이 쓸지
- 정적 페이지라 서버 컴포넌트 + 정적 생성 가능 (메인은 `"use client"`). 페이지별 `metadata`(title/description) 추가 → SEO에도 도움

## 3. 이용약관 페이지 (`/terms`)

### 3-1. 들어갈 내용 (일반적인 약관 구성 기준)

- [ ] 목적 / 용어 정의 (서비스, 회원, 게스트, 닉네임 등)
- [ ] 약관의 게시와 변경 (변경 시 공지 방법, 시행일)
- [ ] 회원 가입: Google 로그인, 닉네임 설정. 게스트 이용 가능 범위
- [ ] 닉네임 규칙: 금지 닉네임(욕설, 타인 사칭, 운영자 사칭 등), 운영자가 변경·제한할 수 있는지
- [ ] 회원 탈퇴 / 이용 제한: 탈퇴 방법, 탈퇴 시 기록 처리
- [ ] 이용자 의무 / 금지 행위: 자동화(봇, 매크로), API 직접 호출·크롤링, 정답 유출 목적의 악용, 랭킹 조작, 서비스 방해
- [ ] 서비스 제공 / 변경 / 중단: 무료 서비스, 점검·장애로 인한 중단, 문제 교체, 기능 변경
- [ ] 게임 기록: 기록 정정·삭제 가능 여부, 게스트 기록(기기 저장)의 유실 책임
- [ ] 권리 귀속: 서비스·문제 데이터·유사도 결과의 저작권, 원작(꼬맨틀) 관계 표시
- [ ] 면책: 유사도 결과의 정확성, 무료 서비스로서의 책임 범위
- [ ] 분쟁 해결 / 준거법 / 관할
- [ ] 문의처
- [ ] 부칙: 시행일

### 3-2. 고민할 것

- **개인정보처리방침을 같이 만들지** (추천: 같이)
  - 푸터 링크가 이미 있고, 1-3처럼 Google 계정·닉네임·식별자·행태 정보를 수집 중
  - 개인정보를 수집하는 서비스는 처리방침 공개가 법적 의무에 가까움(약관보다 우선순위 높음). 수집 항목, 목적, 보유 기간, 제3자 제공·처리 위탁(Supabase, Amplitude, Make.com, Google), **국외 이전**, 파기, 이용자 권리, 책임자 연락처가 들어가야 함
  - 정확한 필수 항목은 법률 검토 또는 개인정보보호위원회 작성 지침 / 표준 양식으로 확인 필요
- **운영 주체 표기**: 개인 / 팀 / 사업자. 약관과 처리방침에 운영자명·연락처가 필요
- **동의 절차**
  - 로그인(가입) 시 약관·처리방침 동의를 받을지: 닉네임 설정 모달에 체크박스 or "계속하면 동의한 것으로 간주" 문구
  - 이미 가입한 유저 처리 (다음 로그인 때 동의 모달 / 공지로 갈음)
  - 동의 이력을 저장할지 (`profiles`에 동의 버전·시각)
- **회원 탈퇴 기능이 없음**: 약관에 탈퇴를 쓰려면 기능(또는 문의를 통한 처리 절차)이 먼저 필요. 백엔드 협의
- **공유 링크의 `sharer_id`**: 로그인 유저의 user id가 URL에 노출되고, 그 id로 당일 통계가 인증 없이 조회됨. 처리방침에 쓰거나 공유 방식 변경 검토 (`docs/todo/share.md`와 연결)
- **피드백**: Make.com 웹훅 URL이 클라이언트에 노출, 본문이 Amplitude 이벤트에도 들어감. 처리방침 반영 또는 정리
- **문의하기 링크**: 현재 `#`. 이메일 / 오픈채팅 / 기존 설문 다이얼로그 중 무엇으로 연결할지
- **버전 관리**: 시행일 표기, 개정 시 이전 버전 보관 방식 (`/terms?v=` 또는 페이지 하단 "이전 약관" 목록), 개정 공지는 공지사항으로
- **랭킹 도입 시점**: 닉네임이 공개되고 기록 조작 제재가 필요해지므로, 랭킹 전에 약관이 있어야 함
- 문구 형식: 법률 문서체 vs 쉬운 말 요약 + 전문
