# 공유 (향후 개편 예정)

공유를 두 가지로 나눠서 본다.

| | 대결형 공유 | 자랑형 공유 |
| --- | --- | --- |
| 목적 | 친구에게 같은 문제를 풀게 하고 시도 횟수로 겨루기 | 내 결과를 보여주기 |
| 받는 사람이 보는 것 | 링크 → 들어와서 풀면서 비교 | 결과 이미지 / 카드 (들어오지 않아도 내용이 보임) |
| 상태 | 구현돼 있음 ("도전장 보내기") | 없음. **이번 개편의 대상** |

> **수정 필요 (2026-11-13)**: 결과 상자 정리(`docs/tasks/ui/result-box/plan.md`)로 버튼 이름이 "도전장 보내기" → **"공유하기"**로 바뀌고, 버튼이 결과 상자 안으로 들어갔으며 위의 "친구는 나보다 빨리 맞힐까요?" 문구는 빠졌다. 이 문서의 "도전장 보내기" 표기와 A-1 노출 조건을 맞춰야 한다. 대결형·자랑형을 한 버튼으로 둘지, 버튼 이름을 어떻게 나눌지도 개편 때 정한다 (excel도 결과 블록에 같은 "공유하기"를 둔다, `specs/excel-ui/decisions.md` Dec-4)

개편의 초점은 자랑형 공유다. 대결형은 현재 동작과 문제만 기록해 두고, 자랑형과 겹치는 부분만 같이 손본다.

## A. 대결형 공유 (현재 구현)

내 시도 횟수를 담은 링크를 보내고, 받은 사람은 그 숫자와 자기 시도 횟수를 비교하는 바를 보면서 푼다.

### 관련 코드

| 역할 | 위치 |
| --- | --- |
| 링크 생성 / 링크 진입 처리 | `src/hooks/useShareLink.ts` (classic·excel 공용) |
| 친구 비교 바 | `src/components/CompetitiveBar.tsx` |
| 공유자 기록 조회 | `fetchSharerStats` (`src/utils/api.ts`), `SharerStats` (`src/types/stats.ts`) |
| 테스트 | `NewMantleForm.test.tsx` C-4-3, C-4-4 (classic만) |

### A-1. 보내는 쪽

- 노출 조건: 게임 종료(정답 또는 포기) 후 결과 창 아래에 "도전장 보내기" 버튼
- 버튼을 누르면 아래 링크를 만든다

  ```
  {origin}?utm_source=newmantle&utm_medium=share&utm_campaign=game_completion
    &shared_attempts={N}&game_date={YYYY-MM-DD}
    &sharer_type={user|guest}&sharer_id={uuid}
  ```

  | 파라미터 | 값 |
  | --- | --- |
  | `shared_attempts` | `correctAttempts`. 정답 행의 attempt, 포기 시에는 입력 횟수 N (C-4) |
  | `game_date` | 플레이한 게임 날짜 (KST) |
  | `sharer_type` / `sharer_id` | 로그인: `user` + Supabase user id / 비로그인: `guest` + localStorage `newmantle_guest_id`. id가 없으면 둘 다 생략 |

- 전달 방식
  1. `navigator.share`가 있으면 네이티브 공유 시트 (`url`만 전달, 제목·본문 없음)
     - 사용자가 취소(`AbortError`)하면 아무것도 하지 않음
     - 그 외 실패는 2번으로 넘어감
  2. 클립보드 복사 + 토스트 (성공 / 실패)
- Amplitude
  - `Result Shared` { method: `Native Share` | `Link Copy`, attempts, theme }
  - `Share Error` { method: `Link Copy`, errorType: `Clipboard Write Failed`, theme }
- 서버에 저장되는 것은 없음. 공유 내용은 전부 URL에 들어 있음

### A-2. 받는 쪽

`gameDate`가 정해진 뒤 URL 쿼리를 한 번 읽는다.

1. `game_date`가 있고 오늘 게임 날짜와 다르면 **전부 무시** (비교 바 없음, URL도 그대로 둠)
2. `shared_attempts`가 숫자면 친구 기록으로 사용 → 비교 바 노출
3. `sharer_type` + `sharer_id`가 있으면 `GET /v2/stats/{sharer_type}/{sharer_id}/{date}` 조회 (인증 헤더 없음, 3초 타임아웃)
   - 응답의 `hint_count`만 사용 ("친구 힌트 n회 사용", B-4). `guess_count`, `status`는 쓰지 않음
   - 실패(404 포함)하면 조용히 힌트 문구만 숨김
4. `shared_attempts` 또는 `sharer_id`가 있었으면 `history.replaceState`로 쿼리를 지움 (UTM 포함)

읽은 값은 컴포넌트 state에만 있다. localStorage에 저장하지 않으므로 **새로고침하면 비교 바가 사라진다.**

### A-3. 친구 비교 바 (`CompetitiveBar`)

- 표시: 나의 시도 / 친구의 기록 / 가운데 VS (게임 종료 후에는 결과)
- 나의 시도: `solvedAttempts ?? correctAttempts`. 진행 중에는 입력 횟수, 종료 후에는 종료 시점 값으로 고정 (이후 입력은 반영 안 됨)
- 결과: 종료(정답 또는 포기) 후 시도 횟수만 비교해서 적으면 승리, 같으면 무승부, 많으면 패배
- 바 길이: `100 - 나의 시도 / (친구 기록 × 2) × 100` %. 친구 기록의 2배를 쓰면 0
- 힌트 횟수는 문구로만 보여주고 승패에는 반영하지 않음

### A-4. 확인된 문제

기록의 신뢰성

- 포기한 유저도 공유 가능하지만 링크에 포기 여부가 없음 → 친구에게는 "N번 만에 맞힘"처럼 보임
  - 서버 stats의 `status`(`FAIL`)로 구분할 수 있지만 현재 쓰지 않음
- 받는 쪽도 포기로 끝내면 시도 횟수만 비교함 → 적게 입력하고 포기하면 "승리!"
- 친구 기록은 URL의 `shared_attempts`를 그대로 믿음 → 숫자를 고쳐서 보낼 수 있음. 서버 `guess_count`와 대조하지 않음
- 힌트 사용이 승패에 반영되지 않음 (랭킹 가중치와 같은 문제, `docs/todo/ranking.md`)

동작상의 구멍

- 입력 0개로 포기 후 공유(C-1에서 허용)하면 `shared_attempts=0` → 바 길이 계산이 0으로 나누기가 됨
- 새로고침하면 비교 바가 사라짐 (URL은 지워졌고 저장도 안 함)
- 날짜가 지난 링크는 아무 안내 없이 일반 접속과 똑같이 보임. 이 경우 쿼리도 지워지지 않고 남음
- `sharer_id`가 URL에 노출되고, stats 조회 API는 인증 없이 id + 날짜로 조회 가능

대결로서 부족한 점

- 단방향: 도전을 받은 사람의 결과가 보낸 사람에게 돌아가지 않음
- 받는 쪽은 친구가 누구인지 알 수 없음 (닉네임 없음)
- 여러 명의 도전장을 받으면 마지막 것만 보임

코드

- 테스트는 C-4-3, C-4-4 두 개뿐 (classic). 네이티브 공유, 날짜 불일치, 힌트 조회, excel 테마는 미검증

해결된 항목

- 포기 시 공유 링크의 시도 횟수가 결과 창보다 1 많던 문제 (N+1) → N으로 통일 (C-4, hint-giveup-fix, 테스트 C-4-3)

## B. 자랑형 공유 (개편 대상)

아직 구체화 전이라 방향과 정해야 할 것만 기록.

### 현재 상태

자랑형으로 쓸 수 있는 것이 없다.

- 공유되는 것은 링크뿐이고 결과 내용(시도 횟수, 힌트 등)이 링크 밖에서는 보이지 않음
- 미리보기 카드는 `src/app/layout.tsx`의 고정 OG 메타데이터 (제목, 설명, `/newmantle_opengraph.webp`). 누가 어떤 결과로 공유하든 같은 카드
- 결과 창(`GameResult`)에는 "N번째 만에 맞히셨네요" 문구만 있어 캡처해도 보여줄 내용이 적음

### 방향

두 가지 경로를 생각 중이다.

#### B-1. 결과 이미지 저장 (다운로드 / 캡처)

결과를 한 장의 이미지로 만들어 주고, 어디에 올릴지는 유저에게 맡긴다. 플랫폼 제약이 없어 인스타 스토리, 단톡방, 커뮤니티 어디든 쓸 수 있다.

- 만드는 방법 후보
  - 클라이언트 렌더: 결과 카드 DOM을 이미지로 변환 (`html-to-image` 등). 서버 불필요. 폰트(Pretendard) 임베드, iOS Safari 호환성 확인 필요
  - 서버 렌더: `next/og`(`ImageResponse`)로 이미지 라우트 추가. B-2의 OG 이미지와 같은 그림을 재사용할 수 있음
- 전달 방법
  - 다운로드 버튼
  - 모바일: `navigator.share({ files })`로 이미지 자체를 공유 시트에 넘기기 (지원 여부는 `navigator.canShare`로 확인, 미지원 시 다운로드)
  - 이미지 클립보드 복사 (데스크톱)
- 캡처하기 좋은 결과 화면 자체를 만드는 것도 방법. 결과창(`docs/tasks/ui/result-box/plan.md`)과 같이 설계

#### B-2. 카드 형태 공유 (카카오톡 / 디스코드)

링크를 붙이면 메신저에 결과가 담긴 카드가 뜨게 한다. 플랫폼마다 방식이 다르다.

| 플랫폼 | 방식 | 필요한 것 |
| --- | --- | --- |
| 디스코드 (및 슬랙, X 등) | 링크의 OG 메타데이터로 카드 생성 | 결과별 공유 URL + 동적 OG (`generateMetadata` + OG 이미지 라우트) |
| 카카오톡 (링크 붙여넣기) | 위와 같음 (OG 스크랩) | 위와 같음 |
| 카카오톡 (공유 버튼) | Kakao JS SDK의 메시지 공유 (피드 템플릿: 이미지, 제목, 설명, 버튼) | Kakao Developers 앱 등록, JS 키, 도메인 등록, SDK 로드 |

- 동적 OG를 하려면 **결과가 URL만으로 결정**돼야 한다. 크롤러는 로그인도 localStorage도 없다
  - 결과를 쿼리에 담기: 서버 변경 없음. 조작 가능 (대결형의 `shared_attempts`와 같은 문제)
  - 공유자 id + 날짜로 서버 조회: `GET /v2/stats/{type}/{id}/{date}`를 그대로 쓸 수 있음 (`status`, `guess_count`, `hint_count`). 조작 불가. id 노출 문제는 그대로
  - 공유 전용 id를 서버에서 발급: 가장 깔끔하지만 백엔드 작업 필요
- 현재 홈(`/`)은 클라이언트 컴포넌트이고 공유 쿼리를 읽은 뒤 지운다. 공유 전용 경로(예: `/share/...`)를 두고 메타데이터만 만든 뒤 홈으로 보내는 구조가 필요할 수 있음
- OG 카드는 플랫폼이 캐시한다. URL이 결과마다 달라야 하고, 같은 URL의 내용이 바뀌면 반영이 늦다

### 정해야 할 것

- **무엇을 보여줄지**
  - 후보: 날짜, 시도 횟수, 힌트 사용 횟수, 포기 여부, 유사도 / 순위 흐름 (워들의 색 블록처럼 과정을 요약한 그림), 연속 정답 일수
  - 흐름을 그리려면 입력 순서별 순위가 필요. 지금은 localStorage의 `submittedWords`에만 있고 서버 stats에는 횟수만 있음 → 클라이언트 렌더(B-1)면 가능, 서버 조회 방식(B-2)이면 쿼리에 담거나 API 확장 필요
- **스포일러**: 정답과 입력한 단어는 카드에 넣지 않는다 (같은 날 아직 안 푼 사람이 봄). 초성 힌트 사용 여부 정도는 가능
- **포기한 경우**: 공유를 막을지, "포기"로 표시하고 허용할지. 대결형의 포기 표시 문제(A-4)와 같이 결정
- **테마**: 이미지 / 카드 디자인을 classic, excel 따로 둘지 하나로 통일할지
- **대결형과의 관계**: 버튼을 따로 둘지, 하나의 공유 창에서 고르게 할지. 자랑형 카드를 누르고 들어온 사람에게 비교 바를 보여주면 두 흐름이 이어짐
- **순서**: B-1(클라이언트 렌더)은 프론트만으로 가능해 먼저 하기 쉬움. B-2는 공유 URL 설계와 카카오 앱 등록이 선행돼야 함
- **측정**: `Result Shared`의 `method`에 이미지 저장 / 카카오 / 링크 복사를 구분해서 기록
