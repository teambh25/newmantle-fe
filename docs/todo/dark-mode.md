# 다크 모드 (향후 계획)

화면 색을 다크 테마로 바꾸는 기능. 아직 시작 전이라 현황과 작업 순서만 기록한다.

## 현황 (2026-11-25 확인)

- `tailwind.config.ts`에 `darkMode: ["class"]` 설정됨
- `src/app/globals.css`의 `.dark` 아래에 다크 색 변수(`--background`, `--card`, `--border` 등) 정의됨
- `components/ui`(shadcn)는 `bg-background`, `text-muted-foreground` 같은 의미 토큰을 써서 변수만 바뀌면 같이 바뀜
- 다크 클래스를 붙이는 테마 제공자·토글 없음 (`layout.tsx`에 없고 `next-themes` 같은 의존성도 없음)
- 화면 코드 대부분이 Tailwind 기본 색을 직접 씀: `bg-white` 약 52곳, `text-gray-*` 100곳 이상, `bg-blue-600`, `border-gray-200` 등. 컴포넌트 파일 약 50개 이상
- 인라인 스타일로 색을 지정하는 곳도 있음 (약 86줄, 확인 필요)
- `dark:` 변형은 거의 없음 (`StatsCalendar.tsx`, `alert.tsx` 정도)

→ 토큰이 준비돼 있지 않은 화면은 다크에서 흰 배경에 연한 회색 글씨가 남아 깨질 가능성이 큼

## 작업 단계 (안)

1. 테마 전환 구조: 토글(또는 시스템 설정 따르기)과 `.dark` 클래스 부착, 저장 위치 결정
2. 화면 하나(메인 게임 화면)만 의미 토큰으로 바꿔 결과를 확인하고 방식 확정
3. 나머지 화면을 같은 방식으로 확장 (`bg-white`→`bg-background`/`bg-card`, `text-gray-500`→`text-muted-foreground` 등)
4. 판단이 필요한 부분 별도 정리

## 결정할 것

- 기본값: 시스템 설정 따르기 / 항상 라이트 / 사용자 선택 중 무엇인지
- 토글 위치 (푸터, 설정 영역 등)
- 게임 결과 색(성공·실패·힌트 단계), 통계 달력 색은 다크에서 의미와 대비를 따로 정할지. 색만 뒤집으면 구분이 흐려질 수 있음
- `excel` 테마도 같이 바꿀지, classic만 먼저 할지
- 인라인 스타일 색을 토큰이나 클래스로 옮길지

## 확인할 것

- 명도 대비(WCAG 기준) 충족 여부
- 실제 화면에서 눈으로 확인 (자동 테스트로는 잡기 어려움)
- 모바일 실기기에서 색 표시
