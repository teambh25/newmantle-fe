# 공지사항 페이지 분리 (계획)

메인 페이지 하단에 공지 전체를 띄우던 것을 `/notices` 페이지로 분리하고, 메인에는 최신 공지만 남긴다. 아직 구현 전이라 방향과 결정할 것만 기록.

## 배경

- 메인(`src/app/page.tsx`)이 `src/static/notifications.ts`의 공지 전체를 최신순으로 렌더링 (classic / excel 각각 `NotificationFeed`)
- 업데이트할 때마다 공지가 늘어나 메인이 길어짐. 2025-09 사과문 같은 오래된 글도 계속 메인에 노출됨
- 매일 접속하는 유저에게 필요한 건 최근 1~2개

## 제안

### 1. `/notices` 페이지

- 전체 공지 목록, 최신순
- 데이터가 정적(`notifications.ts`)이라 정적 생성으로 충분
- 메인 헤더나 메인 공지 영역의 "전체 보기"에서 진입
- 개별 공지 URL(`/notices/[id]`)은 보류. 커뮤니티 등에 공지 링크를 공유할 일이 생기면 추가

### 2. 메인에는 최신 공지 1개 + "전체 보기" 링크

- 개수 고정 방식 추천. "최근 N일 이내만 노출"은 공지가 뜸하면 영역이 통째로 사라짐
- 결정 필요: 1개 / 2개

### 3. N 배지(읽음 처리) 역할 분리

현재 `useNotifications`는 마운트 시점에 `newmantle_last_notification_check`를 현재 시각으로 덮어씀. 메인에 최신 1개만 보이는 상태에서 이 동작을 유지하면 **메인 방문만으로 안 본 공지까지 전부 읽음 처리됨**.

- 읽음 처리(마지막 확인 시각 갱신)는 `/notices` 방문 시에만
- 메인은 읽기만 함: 새 공지가 있으면 "전체 보기" 옆이나 헤더에 N 표시
- 기존 저장값(`newmantle_last_notification_check`)은 그대로 이어서 사용 (키 변경 X → 기존 유저의 읽음 상태 유지)
- 같이 볼 것: 공지 `date`는 날짜만(`YYYY-MM-DD`, UTC 자정으로 파싱)이고 확인 시각은 ISO 시각이라, KST 기준 당일 새벽에 확인한 경우 비교가 어긋날 수 있음 (`docs/tasks/kst-date-fix` 참고)

### 4. 테마

- 메인의 공지 영역은 classic / excel 둘 다 필요
- `/notices` 페이지
  - 선례: `/stats`는 excel 테마에서도 classic UI만 있음
  - 결정 필요: classic만 / excel도 지원
  - excel 지원 시 하단 탭 바(현재 "게임" 탭만 있음)에 "공지사항" 탭을 추가하는 형태가 자연스러움

### 5. 중복 로직 정리

- 정렬, 타입 라벨/색상 로직이 classic / excel `NotificationFeed`에 중복돼 있고, 정렬 방식도 다름 (`Date` 비교 vs 문자열 비교)
- 분리하면서 "최신순 목록", "최신 N개", "새 공지 여부"를 한 곳(예: `useNotifications` 또는 `src/static/notifications.ts` 옆 유틸)으로 모음

## 대안 (채택 안 함)

- 페이지 분리 없이 메인에서 최신 1개만 펼치고 나머지는 "이전 공지 보기"로 접기
  - 작업량은 적지만 excel 테마의 행 번호 레이아웃(`startRow`, 빈 행 채우기)과 맞추기 번거롭고, 공지가 쌓이면 결국 분리하게 됨

## 진행 시

- CLAUDE.md 워크플로대로 `docs/tasks/<task>/verification.md`에 케이스부터 작성
- 현재 공지 관련 테스트 없음 (`NotificationFeed`, `useNotifications`)
- 검증 후보
  - 메인에 최신 공지 1개만 보이고 "전체 보기" 링크가 있음
  - `/notices`에 전체 공지가 최신순으로 보임
  - 메인 방문만으로는 마지막 확인 시각(`localStorage`)이 갱신되지 않음
  - `/notices` 방문 후 메인에서 N 표시가 사라짐
  - 새 공지가 추가되면 메인에 N 표시가 다시 뜸
  - (excel 지원 시) 두 테마에서 모두 동작
