# 결과창 (향후 계획)

게임 종료(정답 / 포기) 후 보여줄 결과창. 랭킹도 결과창에 포함한다. 아직 구체화 전이라 논의된 내용만 기록.

## 보여줄 것

### 1. 정답 선정 이유

- 정답을 맞히면 guess 응답의 `answer`로 옴 (`docs/api/game-v2.md`). 포기 응답도 같은 형태
- 현재 `Answer` 필드는 `word`, `tag`(품사), `description`(단어 설명)뿐
  - 확인 필요: "선정 이유"가 `description`을 말하는지, 별도 필드를 백엔드에 추가해야 하는지

### 2. 시도 횟수 / 힌트 사용 횟수

- 힌트 사용 횟수는 초성 힌트 포함
- 확인 필요: 현재 초성 힌트가 카운트되지 않는 것으로 보임
  - 프론트 `hintUsed`는 일반 힌트만 셈 (Amplitude 분석용, `docs/spec/hint-giveup.md` B-4)
  - 횟수 기준인 서버 `hint_count`가 초성 힌트(`hint/0`) 요청도 세는지 확인 필요
- 포기 시 시도 횟수는 입력 횟수 그대로 N (C-4)

### 3. 랭킹

- 기준
  - 선착순: 그날 몇 번째로 맞췄는지
  - 시도 횟수: 얼마나 적은 시도로 맞췄는지
- **힌트 사용 횟수에 따른 가중치 적용 필요**
  - 시도 횟수만 보면 힌트를 많이 쓸수록 유리해짐
  - 후보: 힌트 미사용자 별도 랭킹 / 힌트 1개를 시도 n회로 환산 / 힌트 수 → 시도 횟수 순 정렬 / 초성 힌트·포기 기록 제외
- 힌트 순위는 유저마다 다름 (최고 순위 × 0.75, A-5). 힌트 1회의 효과가 비율로 같으므로 공정성은 힌트 순위가 아닌 랭킹 가중치로 맞춘다

### 4. Top 1000 단어 공개

- 게임 종료 후에만 1000위 이내 단어 공개
- 추가로 단어별 만족 / 불만족을 조사하면 나중에 평가 데이터로 쓰기 좋음

## 같이 볼 항목 (`docs/spec/hint-giveup.md`)

- B-4: 초성 힌트를 힌트 사용 횟수에 포함하는지 (→ 2번, 3번)
- C-4: 포기 시 기록할 시도 횟수 (→ 2번)
- D-2: 힌트 연속 클릭 시 중복 요청 → 서버 통계(힌트 횟수) 중복 기록. 요청 중 버튼 잠금으로 대응 (hint-giveup-fix). 랭킹 도입 전 서버 기록이 실제로 중복되지 않는지 확인 필요
- D-3: 3초 타임아웃 시 서버는 처리했을 수 있어 재시도하면 `hint_count`가 실제보다 커질 수 있음. 랭킹 가중치에 `hint_count`를 쓴다면 고려 필요
