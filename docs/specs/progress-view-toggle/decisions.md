### Dec-1. 상단바는 무엇을 되살리나
영향도: significant · 출처: ai-suggested

문제 — "기존 상단바"를 어떤 모양과 규칙으로 되살리나?
옵션
  (A) 카드 전 상단바를 코드 그대로
  (B) 표 한 줄 모양은 카드 전 그대로, 표시 규칙은 그 뒤 바뀐 지금 기준
  (C) 카드 작업 중 검토했던 "윗표 + 진행도 바"
선택 — B
근거 — 카드가 배너로 가져간 안내(미등록 단어, 요청 실패)는 지금 다른 자리가 없어서 A면 상단바를 고른 유저가 이 안내를 못 본다. 기록 표의 단계 색·아이콘도 이미 바뀌어서 윗줄만 옛 규칙이면 같은 단어가 다르게 보인다. 코드는 커밋 `75e3d60`에 남아 있다
영향 — Scope, Dec-7, Dec-8
상태 — active

### Dec-2. 범위는 classic만
영향도: local · 출처: user-suggested

문제 — 전환을 excel에도 두나?
옵션
  (A) classic만. 토글은 classic 화면에만
  (B) 테마 선택을 classic(카드) / classic(상단바) / excel 셋으로
선택 — A
근거 — excel은 카드 대신 순위 그래프를 쓰고, 고르기가 필요하면 따로 다룬다. 테마와 방금 입력 모양은 다른 축이라 한 선택지에 섞지 않는다
영향 — Scope, Backlog
상태 — active

### Dec-3. 전환은 설정 메뉴가 아니라 화면의 토글로
영향도: significant · 출처: user-suggested

문제 — 유저가 어디서 모양을 바꾸나?
옵션
  (A) 설정 메뉴 안의 선택지
  (B) 방금 입력 자리 근처의 버튼
선택 — B
근거 — 보는 자리에서 바로 비교하고 되돌릴 수 있다. 설정 메뉴 안에 있으면 상단바가 있다는 걸 찾기 어렵다
영향 — Dec-4, Dec-5
상태 — active

### Dec-4. 토글 위치와 모양
영향도: local · 출처: ai-suggested

문제 — 토글을 어디에 어떤 모양으로 두나?
옵션
  위치 (A) 입력창과 방금 입력 자리 사이 오른쪽 한 줄 (B) 카드 안 왼쪽 위 + 상단바 # 칸 (C) 기록 표 머리줄 오른쪽 끝
  모양 (A) 아이콘 두 개를 붙인 토글 (B) 아이콘 하나짜리 버튼 (C) 글씨 토글
선택 — 위치 A, 모양 A
근거 — 위치: 두 모양에서 같은 자리라 바꾼 뒤 그 자리를 다시 눌러 되돌릴 수 있다. B는 모양마다 위치가 다르고 # 칸의 시도 번호와 부딪힌다. C는 첫 단어를 내기 전에는 기록 표가 없어 버튼도 없다. 세로 한 줄이 늘어나는 건 감수한다. 모양: 지금 무엇을 보고 있는지와 다른 선택지가 있다는 게 함께 보인다. 하나짜리는 아이콘이 지금 모양인지 바뀔 모양인지 헷갈린다. 두 버튼에 이름을 주고 눌린 상태로 표시한다. 아이콘은 화면을 보고 정한다
영향 — Phase 1
상태 — superseded by Dec-11

### Dec-5. 기본값과 저장
영향도: significant · 출처: ai-suggested(기본값) · user-suggested(저장)

문제 — 처음엔 어느 모양이고, 고른 값을 기억하나?
옵션
  (A) 모두 카드로 시작 (B) 모두 상단바로 시작 (C) 새 유저는 카드, v1 유저는 상단바
선택 — A. 고른 값은 저장해 다음에 들어와도 유지한다
근거 — 카드 작업 때 "바를 보며 플레이하도록 이끈다"는 방향으로 카드를 유지했고, 그 방향은 그대로다. C는 v1 유저를 가릴 기준이 애매하고(기기가 바뀌면 깨짐), 기존 유저가 카드를 한 번도 써 보지 않게 된다. 저장값을 읽기 전에는 방금 입력 자리를 그리지 않는다. 카드가 잠깐 보였다가 상단바로 바뀌는 깜빡임을 막는다. 자리 높이가 고정이라 아래가 출렁이지 않는다
영향 — Dec-9, Phase 1
상태 — active

### Dec-6. 두 모양의 높이 차이
영향도: local · 출처: ai-suggested

문제 — 카드(약 86px)보다 상단바(약 40px)가 낮은데 표 자리 최소 높이를 어떻게 하나?
옵션
  (A) 최소 높이를 모드와 상관없이 같게
  (B) 모드마다 따로
  (C) 상단바일 때 남는 높이만큼 기록 표 줄을 늘림
선택 — A
근거 — 전환할 때 기록 표와 푸터가 움직이지 않는다. C는 기록 표 기본 줄 수·더보기 규칙까지 모드마다 갈라져 범위가 커진다. 빈 공간은 단어가 쌓이기 전에만 보인다
  - → 최소 높이는 단어가 쌓이기 전에만 효과가 있다. 단어가 쌓인 뒤에는 전환하면 기록 표·푸터가 높이 차이만큼 움직인다. 화면에서 보니 어색하지 않아 감수한다 (2026-11-17, 사용자)
영향 — Phase 1, Backlog
상태 — active

### Dec-7. 상단바 모드의 기록 표에 방금 단어를 넣나
영향도: significant · 출처: ai-suggested

문제 — 지금 기록 표는 방금 단어까지 모든 단어를 담는다(카드가 생긴 뒤 바뀐 규칙). 상단바 모드에서도 그럴까?
옵션
  (A) 모드마다 다르게: 상단바는 방금 단어를 상단바에만 두고 다음 항목이 오면 기록 표로 옮김, 카드는 지금처럼 포함
  (B) 둘 다 지금 규칙
선택 — A
근거 — 상단바와 기록 표는 머리줄을 같이 쓰는 한 표처럼 보여, 같은 단어가 겹치면 카드 전에 불편했던 문제("다음 항목이 올 때 옮김"으로 정했던 것)가 돌아온다. 카드는 모양이 달라 겹쳐도 괜찮았다. 모드에 따라 갈라지는 건 기록 표 고르기 하나라 `buildBoard`에서 모드를 받아 처리한다
영향 — Phase 1
상태 — active

### Dec-8. 상단바 방금 입력 줄의 안내
영향도: local · 출처: ai-suggested

문제 — 카드 전 상단바 줄은 제출 실패만 보여 줬고, 힌트·초성 힌트·포기 실패는 입력창 아래 문구였다. 그 자리가 지금은 없다. 어떻게 보여 주나?
옵션
  (A) 상단바 방금 입력 줄에 아이콘 + 짧은 실패 문구로
  (B) 입력창 아래 문구를 모드와 상관없이 되살림
선택 — A. 미등록 단어 표기도 카드 배너와 같은 기준으로
근거 — "방금 무슨 일이 있었나"를 보여 주는 자리가 모드마다 하나씩(카드 배너 / 상단바 줄) 있고, 실패도 그 자리에 두면 무엇이 오는지(`latest`)는 공유하고 그리는 부분만 갈라진다. 사라지는 때와 연속 실패 토스트도 카드와 같다. B는 카드 모드에서 같은 안내가 두 번 나온다
영향 — Phase 1
상태 — active

### Dec-9. 저장 위치와 분석
영향도: local · 출처: ai-suggested

문제 — 고른 모양을 어디에 저장하고 어떻게 측정하나?
옵션
  (A) 테마와 같은 방식: localStorage + Amplitude 사용자 속성 + 전환 이벤트. 기기마다 따로
  (B) 로그인 계정에 저장해 기기 간 유지
선택 — A
근거 — 테마도 기기별 저장이라 맞고, 백엔드 작업이 없다. 상단바를 고른 비율과 모드별 완료율·시도 수로 "상단바가 낫다"가 일부 의견인지 볼 수 있다. 사용자 속성이 있으면 기존 게임 이벤트를 모드별로 나눠 볼 수 있다. 키·이벤트·속성 이름은 구현하며 정한다. 정한 이름: localStorage `newmantle-progress-view` (`card` / `bar`), 사용자 속성 `progress_view`, 이벤트 `Progress View Switched` (`{ view }`, 테마의 `Theme Switched`와 맞춤)
영향 — Phase 1, Backlog
상태 — active

### Dec-10. 테스트 범위
영향도: local · 출처: ai-suggested

문제 — 두 모양을 어디까지 테스트하나?
옵션
  (A) 로직은 모드별 기록 표 고르기와 저장값 읽기, 화면은 전환·저장값 시작·실패 대표 하나
  (B) 상단바 경우별 칸 내용까지 화면 테스트, 카드 전 상단바 테스트를 되살림
선택 — A
근거 — 방금 입력 줄에 무엇이 오는지는 카드와 같은 계산을 쓰고 이미 테스트가 있다. 같은 규칙을 두 층에서 보지 않는다. 카드 전 상단바 테스트는 그 뒤 기록 표 규칙과 표기가 바뀌어 대부분 맞지 않는다. 칸 모양은 화면 확인으로
영향 — Verification
상태 — active

### Dec-11. 토글을 표 안의 늘리기 / 줄이기 버튼으로
영향도: local · 출처: user-suggested

문제 — 입력창과 방금 입력 자리 사이에 토글 줄(약 40px)을 따로 두니, 맞춰 둔 화면 높이가 깨져 모바일에서 더보기가 잘린다. 토글을 어디에 어떤 모양으로 두나?
옵션
  (A) 지금처럼 두 아이콘 토글, 날짜 줄 오른쪽 끝으로 옮김
  (B) 두 아이콘 토글을 입력창과 카드 사이 빈칸에 작게
  (C) 버튼 하나로 늘리기 / 줄이기. 카드 = 늘린 모양, 상단바 = 줄인 모양. 버튼은 방금 입력 자리 안 오른쪽 위
선택 — C. 카드는 오른쪽 위 모서리에 줄이기, 상단바는 머리줄 오른쪽 끝(유사도 칸)에 늘리기. 아이콘은 접기 / 펼치기 화살표
근거 — 따로 차지하는 줄이 없어 높이가 늘지 않고, 버튼이 보는 자리 안에 있다. 두 모양에서 같은 오른쪽 위라 같은 자리를 다시 눌러 되돌릴 수 있다. Dec-4에서 버튼 하나를 뺀 이유(지금 모양인지 바뀔 모양인지 헷갈림)는 늘리기 / 줄이기라는 뜻으로 풀린다. 카드 왼쪽 위는 제출 횟수가 쓰고 있다. 두 아이콘 토글보다 눈에 덜 띄는 건 감수한다
영향 — Phase 1, Verification
상태 — superseded by Dec-12

### Dec-12. 표 머리줄 # 칸의 게이지 스위치
영향도: local · 출처: user-suggested(위치·모양) · ai-suggested(스위치가 끄고 켜는 것)

문제 — 오른쪽 위 화살표 버튼(Dec-11)은 너무 눈에 안 띈다. 어디에 어떤 모양으로 두나?
옵션
  위치 (A) 두 모양 모두 표 머리줄 # 칸: 카드는 그 아래 기록 표 머리줄, 상단바는 상단바 머리줄 (B) 카드 안 왼쪽 위 + 상단바 # 칸 (C) 설정 메뉴 안 (테마 바꾸기 옆)
  모양 (A) 켜기 / 끄기 스위치 (B) 처음의 아이콘 두 개 토글
  켜짐 색 (A) 앱 파랑 (B) 연한 파랑 (C) 진한 회색
선택 — 위치 A, 모양 A, 켜짐 색 A. 스위치가 켜고 끄는 것은 게이지: 켜짐 = 카드, 꺼짐 = 상단바. 카드 모드에서도 기록 표 머리줄은 단어가 없어도 늘 보인다
근거 — 위치: 두 모양에서 "표 머리줄 # 칸"이라는 같은 규칙이고, 카드 안 제출 횟수와 부딪히지 않는다. 첫 단어 전에는 기록 표가 없어 스위치가 안 보이던 문제(Dec-4가 기록 표 쪽을 뺀 이유)는 머리줄을 늘 보여 줘서 푼다. 전환하면 스위치가 위(상단바) / 아래(카드)로 옮겨 가 같은 자리를 다시 눌러 되돌릴 수 없는 건 감수한다. 모양: 모바일 # 칸(48px)에 아이콘 두 개를 넣으면 너무 작아 다시 눈에 안 띈다. 스위치는 생김새로 바꿀 수 있다는 게 보이고 켜짐 / 꺼짐으로 지금 모양을 알 수 있다. 무엇을 끄는지는 글자 없이 안 보이므로 마우스를 올리면 이름을 보여 주고, 부족하면 # 칸을 넓혀 글자를 붙인다. 위치 C는 화면이 깔끔하지만, 스위치가 필요한 유저(카드가 불편한데 바꿀 수 있는 걸 모르는 유저)가 못 찾는다. 공지로 알려도 나중에 온 유저에게는 닿지 않는다. 옮길지는 전환 이벤트 숫자를 보고 정한다. 켜짐 색: 앱 파랑은 카드를 권하는 느낌이 있지만 기본이 카드라는 의도와 맞고, 연한 파랑은 화면에서 어색했다. 회색은 켜짐 / 꺼짐 구분이 약하다
영향 — Phase 1, Verification
상태 — active

### Dec-13. 카드 모드에 상단바를 같이 두지 않는다
영향도: local · 출처: ai-suggested

문제 — 카드 모드에서 기록 표 머리줄이 상단바 모드와 달라 표의 역할이 바뀌어 보인다. 카드가 있어도 상단바를 두나?
옵션
  (A) 둘 중 하나만 (카드 또는 상단바)
  (B) 카드 모드도 카드 + 상단바 + 기록 표. 스위치는 카드만 숨김
선택 — A
근거 — 처음 설계 의도는 표보다 카드를 보게 하는 것이고, 피드백(상단바가 낫다는 유저)은 기본 카드 + 끌 수 있게 하는 것으로 이미 풀린다. B는 시선이 다시 표로 가고, 같은 단어·실패 안내가 두 번 보이고, 모바일 높이(상단바 한 줄)와 카드를 끌 때 아래가 올라오는 문제가 생긴다. 표 역할이 바뀌는 건 스위치를 직접 끈 유저에게만 생겨서 헷갈림이 크지 않다
영향 — 없음 (현재 구조 유지)
상태 — active
