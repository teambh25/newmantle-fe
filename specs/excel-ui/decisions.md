### Dec-1. excel을 어디까지 맞추나
영향도: foundation · 출처: user-suggested

문제 — classic의 변경을 excel에 어느 범위까지 반영하나?
옵션
  (A) 모든 화면을 기능 동등하게 맞추고, 별도 페이지도 excel 모양으로 만든다
  (B) 최소 유지: 게임만 동작하게 두고, 결과창·실패 안내 등은 classic 전용으로 남긴다
  (C) 중간안: 메인 게임 화면의 동작은 classic과 거의 같게 맞추고, 별도 페이지(`/rule`, `/notices`, `/stats`)는 classic 페이지를 그대로 쓴다
선택 — C
근거 — 목표는 단어를 입력하는 게임 화면을 엑셀에 자연스럽게 어울리게 하는 것이다. 가끔 들르는 페이지까지 excel로 만들면 비용이 크다. A는 별도 페이지마다 excel 껍데기가 필요하다. 또 페이지는 서버 컴포넌트이고 테마는 localStorage에 있어서, 마운트 전까지 빈 화면을 보여 줘야 해 깜빡임이 생긴다. B는 classic을 바꿀 때마다 차이가 계속 벌어진다
영향 — Scope 전체, Dec-11
상태 — active

### Dec-2. 같은 로직을 두 테마가 어떻게 공유하나
영향도: significant · 출처: ai-suggested

문제 — classic `NewMantleForm` 컴포넌트 안에 섞여 있는 화면 로직(결과 상태, 임시 줄, 반복 표시, 보드 계산, 공유 링크)을 excel에서 어떻게 쓰나?
옵션
  (A) excel 작업 전에 공용 훅으로 먼저 뺀다
  (B) excel 컴포넌트에 복사한다
  (C) 순수 함수만 `utils`로 빼고, 상태 전환은 양쪽에 둔다
선택 — A
근거 — "로직은 거의 같게"를 유지하려면 한 곳에 있어야 한다. B는 공유 링크처럼 중복이 하나 더 생긴다. C는 타이머와 상태 전환이 여전히 복제된다. 추출 중에는 기존 classic 테스트가 안전망이 된다. 지금 classic과 excel에 똑같이 복제돼 있는 공유 링크 생성·진입 처리도 이 훅으로 합친다
영향 — Phase 2, Phase 3
상태 — active

문제 — 결과 블록을 어디에 두고 무엇을 담나?

### Dec-8. 진행 상황 카드를 시트 행으로 옮기는 방식
영향도: local · 출처: ai-suggested

문제 — 진행 상황 카드의 정보 중 무엇을 어떤 시트 모양으로 보여 주나?
옵션
  (A) 카드 정보를 전부 시트에 옮긴다 (구간 눈금, 지난 기록 말풍선 포함)
  (B) 방금 입력 행(강조 테두리), 최고 순위 데이터 막대(`gaugeFill`), 시도 횟수만 둔다
선택 — B
근거 — "정보는 같되 바를 시트 행으로"라는 방향과 슴슴한 excel 톤에 맞춘다. 표와 같은 열을 쓰는 행과 데이터 막대는 엑셀에서 익숙한 형태다. 구간 눈금과 지난 기록 말풍선은 셀 안에서 지저분해진다. 세부 모양은 구현한 뒤 사용자 피드백으로 확정한다
영향 — Phase 3
상태 — superseded by Dec-46

### Dec-12. 새 공지 알림

옵션

  (B) 엑셀 레코드처럼 "항목 | 값" 행. 항목은 시도 칸, 값은 단어 칸(모바일은 순위·유사도 칸까지). 순서는 정답 → 설명 → 시도 횟수 → 공유 → 피드백

  - 공유·피드백은 버튼 대신 엑셀 하이퍼링크 모양(파란 밑줄, 13px로 다른 값보다 작게)으로, 값 칸 전체가 누르는 영역(높이 40px)이라 작지 않다. 작게 느껴지면 엑셀 양식 컨트롤 단추(회색 버튼)로 바꿀 수 있다
  - 다음 퀴즈 안내는 결과와 상관없는 정보라 결과 블록에서 뺐다(Dec-75)
